# Примите участие во вкладе

Приглашаем вас сообщать о воспроизводимых проблемах, исправлениях документов, надстройках и общих улучшениях возможностей на китайском или английском языке.

<a id="section-5"></a>
## Где общаться

- [Проблемы](https://github.com/KKKKhazix/agent-autoloop/issues/new/choose): Воспроизводимые неисправности и функциональные предложения с четкими сценариями. Что можно сделать, исправляет специалист по обслуживанию, а результаты ремонта передаются репортеру.
- [Вопросы и ответы по использованию](https://github.com/KKKKhazix/agent-autoloop/discussions/categories/q-a): Установка, правила, настройка агента и канала.
- [Обмен идеями](https://github.com/KKKKhazix/agent-autoloop/discussions/categories/ideas): Обсудить идеи, которые еще не сформировали задачи разработки.
- [Обмен практикой](https://github.com/KKKKhazix/agent-autoloop/discussions/categories/show-and-tell): Делитесь плагинами, шаблонами сцен и опытом использования.
- По вопросам безопасности обращайтесь к сопровождающему в соответствии с [Инструкциями по безопасности](SECURITY.md) и не раскрывайте детали использования в публичных обсуждениях.

<a id="section-13"></a>
## Объем вклада

Новый агент, плагин событий и канал соединяются на уровне плагина; весь бизнес-процесс можно превратить в шаблон сцены. Сначала прочтите [Инструкции по разработке плагина](docs/plugins.md) и [Существующие сценарии](README.md#сценарии), чтобы избежать повторного внедрения.

Ядро поддерживает нулевые зависимости во время выполнения и не подключается к внешним продуктам. Страница обзора, холст рабочего процесса и другие интерфейсы принадлежат независимым клиентам и не размещаются на этом репозитории. Прежде чем менять протокол или основной процесс, сначала объясните конкретные сценарии и влияние совместимости; договоры на обслуживание см. в [AGENTS.md](AGENTS.md), протоколы см. в [docs/protocol.md](docs/protocol.md).

<a id="section-19"></a>
## Отправить изменения

1. Создать ветку от последней `main`; внешние участники используют Fork. Филиалы на этом репозитории могут начинаться только с `claude/`, `codex/` или `dependabot/`, а тег используется только для выпуска (`v1.2.3`). Агент разрабатывается в независимом рабочем дереве, а домашний каталог хранится по адресу `main`.
2. Используйте Node.js 24 или более позднюю версию для запуска `npm ci`. PR решает проблему, а соответствующие инструкции, примеры и конфигурации на китайском и английском языках обновляются одновременно.
3. Чтобы исправить ошибку, сначала напишите неудачный тест, который сможет ее воспроизвести. В начале тестового файла объясняется, какой сбой предотвратить. Чистые документы, шаблоны или небольшие обратимые изменения не копируют и не реализуют тесты.
4. Запустите `npm test`, `npm run typecheck` и `npm run format:check` перед отправкой. Запустите `npm run test:nightly` еще раз, если задействованы журналы, таблицы срока действия или параллелизм. CI проверяется в Linux и macOS, а представленный код используется для запуска дымовой проверки от установки до удаления; эти проверки пропускаются, если изменяется только документ. В PR перед запуском короткого моделирования из 20 000 шагов изменяются только `kernel/` и `protocol/`. После слияния запускается полная проверка. Принудительное уничтожение и проверка мутаций также запускаются регулярно каждый день, а также выполняется быстрый тест с использованием последней версии Node.
5. Отправьте PR по адресу `main`, описав проблему, измененное поведение, результаты проверки и влияние на совместимость. Используйте черновики для незавершенной работы; подтвердите, что две отправленные в данный момент системные проверки пройдены перед объединением. Пожалуйста, установите флажок «Разрешить редактирование сопровождающим»: сопровождающие, которые хотят внести изменения, обычно вносят изменения непосредственно в вашу ветку, а затем объединяют ее. CI Fork работает на компьютере GitHub и запускается автоматически; первый PR для вновь зарегистрированной учетной записи GitHub должен быть одобрен сопровождающим перед запуском.

В тесте использовался временный `AGENT_AUTOLOOP_HOME`, случайный порт, локальный поддельный HTTP и поддельная команда уведомления. Не подключайтесь к реальным бизнес-базам данных, не отправляйте сообщения и не включайте мониторинг событий для приложений Feishu, которые уже подключены к сети. Сценарий реальной доставки создаст и удалит указанный тестовый репозиторий и запустится только тогда, когда пользователь явным образом запросит его.

Не отправляйте ключи, ссылки на разрешенные карты, полные конфигурации, базы данных, выходные данные запуска или профили коллег. Журналы и снимки экрана в вопросе также должны быть сначала десенсибилизированы. Код предоставляется по [Лицензии MIT](LICENSE).

Пользователь установил последнюю версию, а не `main`: изменения в `main` не будут доступны пользователю до следующей версии. Способы установки и обновления см. в [INSTALL.md](INSTALL.md). Правила номера версии см. в разделе [Протокол](docs/protocol.md#section-423); в настоящее время нет ветки долгосрочной поддержки. Автоматическое объединение остается отключенным в настройках репозитория, а плагин доставки выполняет проверку, проверку и объединение в соответствии с [Соглашением о доставке](docs/protocol.md#section-397).
