# Установка Agent Autoloop

Русская адаптация находится в приватном [репозитории](https://github.com/maxwell2010/agent-autoloop-ru). Нужен доступ через Git. Публичная raw-ссылка исходного проекта устанавливает другую версию.

## Требования

- macOS или Linux, Node.js 24+, Git и curl.
- Установленный CLI-агент с входом, выполненным пользователем: например, Codex или Claude Code.
- Для сценариев GitHub и их тестов: авторизованный `gh` и `jq`.

Обычная Windows пока не поддерживается. В WSL2 используйте Linux-версию Node. Для системной службы требуется systemd; без него укажите `--no-service` и запускайте `up` вручную. Уведомления WSL могут не появляться в Windows; используйте `status` или внешний канал.

Проверьте `node --version`. После установки Homebrew `node@24` добавьте его в PATH. Для nvm установите Node 24 и выберите его в текущей оболочке. Не читайте и не копируйте учетные данные агента и не выполняйте вход вместо пользователя.

## Установка

```sh
git clone https://github.com/maxwell2010/agent-autoloop-ru.git
cd agent-autoloop-ru
sh install.sh --no-service --agent codex
```

Замените `codex` на `claude`, если нужен Claude Code. Без `--agent` подключаются все найденные поддерживаемые агенты. Другой CLI задается через `--command 'программа {prompt}'`; адаптер сам по себе не ограничивает права программы.

Приложение устанавливается в `~/.agent-autoloop/app`, настройки и данные - в `~/.agent-autoloop`. Ссылка `agent-autoloop` создается в доступном каталоге PATH. Для отдельной тестовой установки задайте `AGENT_AUTOLOOP_HOME`.

Без `--no-service` установщик регистрирует службу пользователя. В CI, временной среде и WSL без systemd используйте ручной запуск. Сначала проверьте правила и права агента:

```sh
agent-autoloop check
agent-autoloop rules explain
agent-autoloop up
```

`up` запускает обработку правил. После проверки службу можно установить отдельно: `agent-autoloop service install`.

## Проверка полного цикла

В другом терминале выполните `agent-autoloop try`. Команда вызывает реального агента и расходует токены. Она задает вопрос о цвете; после ответа агент продолжает работу.

```sh
agent-autoloop status
agent-autoloop answer 1 2
agent-autoloop status
```

Вместо `1` используйте фактический номер карточки. В интерактивном терминале ответ можно выбрать внутри `try`. Диагностика: `doctor`, хронология: `why <цикл>`.

Для проверок без настоящего агента используйте тестовые программы, временный каталог данных и случайные порты. Не направляйте тестовые сообщения в рабочие каналы и не запускайте второй слушатель Feishu.

## Правила и сценарии

Редактируйте `rules.json`, затем запускайте `agent-autoloop check`. Укажите часовой пояс в `timezone`. Правила применяются автоматически; при ошибке работающий сервис сохраняет последнюю корректную версию.

Доступны готовые [сценарии](README.md#сценарии). Права `read`, `edit`, `full` зависят от адаптера: [ограничения](docs/plugins.md#section-105). Недоступность браузера не является основанием расширять права до `full`.

## Обновление, копии и удаление

`agent-autoloop update` обновляет установку из ее источника. Для адаптации это `maxwell2010/agent-autoloop-ru`. Пока нет release tag, используется `main`. Наличие коммита не означает успешную проверку выпуска. При смене источника установщик останавливается, чтобы не заменить чужую установку.

`backup [каталог]` сохраняет данные и ключи. Храните копию как секрет. Перед `restore <каталог>` остановите сервис: восстановление заменяет базу, конфигурацию, правила и секреты.

`uninstall` удаляет программу и службу, сохраняя данные. `--yes` пропускает подтверждение.
