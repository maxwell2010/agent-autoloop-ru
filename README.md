# Agent Autoloop - русская адаптация

Agent Autoloop принимает события, передает работу командным агентам и продолжает ее после ответа пользователя. Между запусками агента состояние сохраняется в SQLite. Когда нужен ваш выбор, система отправляет карточку.

> Статус этой адаптации: подготовка. Русское введение и схема готовы, полный перевод CLI, протокола и сценариев еще не завершен. Это не проверенный выпуск для эксплуатации. См. [состояние перевода](docs/localization-ru.md) и [проверку безопасности](docs/security-review.ru.md).

## Как устроена работа

1. Источник отправляет событие: расписание, issue GitHub или сигнал вашей системы.
2. Ядро выбирает агента и рабочий каталог по доверенным правилам. События одного дела могут объединяться.
3. Агент выполняет один цикл, печатает результат и завершает процесс.
4. Если требуется решение пользователя, результат содержит вопрос с вариантами ответа.
5. Ответ становится новым событием. Агент продолжает работу, по возможности в прежней сессии.

Ядро не подключается к внешним продуктам. Источники, исполнители и каналы уведомлений подключаются через плагины. Веб-панели нет. Доступны CLI и страница отдельной карточки.

## Требования и установка

Исходная версия поддерживает macOS и Linux, требует Node.js 24+, Git и уже установленного CLI-агента с выполненным входом. Работа в обычной Windows не подтверждена. Для Windows нужен отдельно проверенный WSL2 или Linux.

Не устанавливайте эту адаптацию как готовый релиз: перевод и проверка еще продолжаются. Для изучения исходников:

```sh
git clone https://github.com/maxwell2010/agent-autoloop-ru.git
cd agent-autoloop-ru
```

Основные команды после установки в поддерживаемой среде:

```sh
agent-autoloop init --agent codex --no-service
agent-autoloop check
agent-autoloop rules explain
agent-autoloop up
```

`init` создает конфигурацию и ключи. `--no-service` отключает установку системной службы, но не заменяет чтение и проверку настроек. `up` запускает сервис и обработку правил. `try` обращается к реальному агенту и может расходовать токены.

## Настройка правил

Конфигурация и данные находятся в `~/.agent-autoloop`, правила - в `rules.json`. В поле `to` указывается имя из раздела `agents`.

```json
{
  "name": "Утренний обзор",
  "when": { "cron": "0 9 * * *" },
  "to": "codex",
  "cwd": "~/notes",
  "prompt": "Подготовь обзор вчерашних заметок и изменений. Отвечай на русском языке."
}
```

Часовой пояс задается через `timezone`, например `Asia/Barnaul`. Его следует выбрать под свое расписание. Команда `agent-autoloop emit <тип> --dry-run` показывает предполагаемое назначение без отправки события сервису.

## Ответ агента

Первая строка последнего сообщения содержит итог. Дополнительные действия записываются в JSON-блок `agent-autoloop`. Имена полей протокола переводить нельзя.

````text
Проверка выполнена. Требуется выбрать способ доставки.

```agent-autoloop
{
  "ask": [{
    "title": "Как доставить заказ?",
    "text": "Оба варианта доступны сегодня.",
    "options": ["Курьер", "Самовывоз"],
    "key": "shipping"
  }]
}
```
````

Другие поля результата: `notice` - уведомление, `resolve` - закрытие карточки, `later` - повторная проверка, `events` - новые события в пределах правила. Для совместимости с исходной версией статусы результата пока задавайте маркерами `FAILED` и `NOTHING`.

## Основные команды

| Команда | Назначение |
|---|---|
| `status` | Состояние, карточки, циклы и расходы |
| `answer <карточка> <номер>` | Выбрать ответ |
| `resolve <карточка> <результат>` | Закрыть карточку с пояснением |
| `why <цикл>` | Показать события, правило и результат |
| `doctor` | Проверить настройку |
| `stop <цикл>` | Остановить выполнение |
| `key list` | Показать выданные ключи |
| `key remove <тип> <имя>` | Отозвать ключ |
| `backup [каталог]` | Создать резервную копию с секретами |
| `restore <каталог>` | Восстановить данные после остановки |

## Безопасность

Не давайте автономному агенту доступ к рабочим секретам и важным данным без изоляции. `askFirst` - инструкция модели, а не обязательная проверка каждой системной операции. `access: full` расширяет возможности агента; плагин `command` сам по себе не ограничивает запущенную программу.

Плагины выполняют локальный код. Ссылка на карточку дает ее обладателю право ответить. Резервные копии содержат ключи и должны храниться как секреты. Подробности и границы проверки приведены в [отчете](docs/security-review.ru.md).
