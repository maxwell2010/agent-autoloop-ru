# Запись плагина

Сначала просмотрите [каталог встроенных модулей README](../README.md#плагины), чтобы выбрать существующую реализацию; если требуется расширение, начните со следующих трех минимальных работоспособных шаблонов и замените бизнес-часть:

| Шаблон | Что было продемонстрировано | Что вы хотите заменить |
|---|---|---|
| [Шаблон агента](../examples/plugins/hello-agent/agent.ts) | Используйте `echo` для имитации выполнения, прочитайте выходные данные и номер сеанса | Новая команда запуска агента и анализ выходных данных |
| [Шаблон канала](../examples/plugins/hello-channel/channel.ts) | Получить карту, записать в файл, сообщить о доставке; ответить через командную строку | Отправлять, обновлять и отвечать на обратные вызовы целевой платформы |
| [Шаблон плагина событий](../examples/plugins/hello-source/source.ts) | Проверьте подпись HMAC-SHA256 и преобразуйте смоделированные заказы в события | Метод проверки подписи и отображение полей бизнес-системы |

Плагины событий, исполнители, каналы и командные строки используют один и тот же набор интерфейсов HTTP + JSON. Используйте Shell только для подключения к протоколу, вы можете увидеть [Сценарий заказа](../examples/worker.sh) и [Сценарий канала](../examples/channel.sh): после установки адреса промежуточного офиса и ключа для запуска потребуются `curl` и `jq`. Они подходят для демонстрации коротких задач; более длительные задачи используют возможности пульсации, остановки и возобновления работы встроенного приемщика заказов.

Плагин представляет собой каталог, а вход - `agent.ts`, `channel.ts` или `source.ts`. Используйте модуль `node:` и файлы только в его собственном каталоге, а типы объявляются в плагине; не делайте относительных ссылок на исходный код движка.

Используйте `agent-autoloop add <git адрес>` для установки в `~/.agent-autoloop/plugins/<имя репозитория>`, а также принимайте локальные репозитории Git. Он только клонирует, не устанавливает зависимости, не запускает сценарии установки и не обновляется автоматически. Плагин будет запущен при загрузке, и плагин с таким же именем в каталоге установки будет иметь приоритет.

<a id="section-17"></a>
## Первый запуск

Запустите эту команду в каталоге движка: она загружает три примера во временную промежуточную платформу, фактически завершает проверку, отправку, запуск, уведомление и отчетность и очищает после выхода.

```bash
node --disable-warning=ExperimentalWarning --test --test-name-pattern='agent-autoloop add' tests/example-plugins.test.ts
```

<a id="section-25"></a>
## Плагин агента

Начните с [hello-agent/agent.ts](../examples/plugins/hello-agent/agent.ts). Он заменяет модель на `echo` и может быть клонирован в другом месте для запуска.

| Способ экспорта объектов | Функция |
|---|---|
| `command(turn)` | Возвращает массив параметров команды; параметры не выполняются как шелл-код |
| `read(stdout, code, stderr)` | Возврат `text`, `session`, `usage`, `sessionUsage`, `error`, `finished`, `started`; во время работы `code` - `null` |
| `link(session)` | Необязательно, откройте ссылку на этот сеанс. Если структурированный результат написана неправильно, `read` возвращает `session`. Плагины только переписывают чек, независимо от того, есть ли ссылка |
| `check()` | Необязательно, верните `null`, если он доступен, в противном случае вернитесь к разделу «Что делать дальше» |

`turn` содержит `prompt`, `session`, `resume`, `cwd`, `access`, `model`, `effort`, `command`, `contextFile`, `folder`. `contextFile` - это файл данных, и ограниченному интерфейсу командной строки необходимо разрешить чтение `folder`. `read` должен иметь возможность обрабатывать незавершенный вывод; CLI вернет `text` только после фактического завершения. `read` Если выдается ошибка или ничего не возвращается, работа продолжится. После завершения цикла он не будет завершен, а будет оставлен в исходной сессии и перенесен.

Плагин, который поддерживает `resume`, будет возвращать `started: true` с момента принятия Агентом слова подсказки, в том числе во время работы и после возникновения ошибки. В противном случае, если он отключится в середине работы, он будет расценен как сеанс, который невозможно подключить, и будет открыт новый сеанс для переделки дел. Если возвращается `session`, нажмите `turn.resume`, чтобы вернуться к исходному сеансу: от этого зависит повторная отправка, которая не удалась, и перезапись неправильной структурированного результата; не возвращайте `session`, если CLI не может вернуться.

`usage` представляет собой сумму, использованную в этом запуске. Некоторые интерфейсы командной строки предоставляют только общее количество всего сеанса (токен Кодекса, плата за код Клода). Эти элементы помещаются в `sessionUsage`, и `session` возвращается одновременно. Перед запуском исполнители запишите последнее накопленное значение этого сеанса, вычтите его после окончания и объедините с `usage` для отчетности; эти записи помещаются в `~/.agent-autoloop/worker/usage/`, и исполнитель не будет пересчитана, если ее перезапустить в середине пути.

Нет записанных продолжений (сеансов, существовавших до смены компьютера, обновлений, сеансов, которые были бесполезны более 90 дней) или совокупное значение становится меньше. На этот раз об этих предметах не будет сообщено, и они не будут угадываться; следующее продолжение вернется в норму. Объем, использованный другими программами в том же сеансе, не может быть различен. Например, если я открою ссылку и продолжу общение, это будет засчитано при следующем подключении. Если интерфейс командной строки изменен так, чтобы он сообщал только один раз, подключаемый модуль должен изменить эти элементы обратно на `usage`. Не делайте предположения, основываясь на размере чисел.

Выберите этот плагин в правилах:

```json
{ "name": "Hello", "worker": "my-computer", "use": "hello-agent", "access": "read" }
```

Когда вам нужно напечатать только последнее сообщение, вы можете использовать встроенный `command` для добавления массива параметров, и нет необходимости писать плагин. В параметрах можно использовать `{prompt}`, `{model}`, `{effort}`, `{cwd}` и `{context}`; существуют также переменные среды `AGENT_AUTOLOOP_CONTEXT` (файл данных) и `AGENT_AUTOLOOP_RUN` (круглый) во время выполнения.

DeepSeek Harness имеет встроенный плагин `dsh`. `use: "dsh"` написано в правилах. Если требуется версия 0.2.2 или новее, будет проверен `agent-autoloop doctor`. Теперь `latest` npm все еще является старой версией, поэтому вам нужно установить ее следующим образом: `npm install -g @deepseek-ai/dsh@next --allow-scripts=koffi,node-pty,@deepseek-ai/dsh-subprocess-local`. Новая версия npm по умолчанию не запускает зависимые сценарии установки и не выпускает эти три пакета. После установки выглядит нормально, но после запуска возникает ошибка. Версия 0.2.2, обновленная со старой версии, возможно, не сможет прочитать `refs` в `~/.dsh/.credentials.yaml` и сообщит `MISSING_CREDENTIAL`: поместите ключ в переменную среды и поместите системную службу Linux в `~/.config/environment.d/*.conf`. Сообщается только о токене, а не о комиссиях. Некоторые пользователи использовали 0.2.2-rc.1 и сторонние OpenAI-совместимые службы на WSL2 для прохождения тестов вопросов и ответов, использования и `resume`. Он выполняется один цикл с `dsh headless --json`, получает номер сеанса из события `session`, использует `--session-id` для продолжения, суммирует использование `step_end` в Token, и событие `final` считается завершенным; `access` каждый раз сопоставляется с `--permission-mode`, и вызов утверждается VIP. `--approval-policy never` напрямую отказывается. `model` и `effort` в правилах не работают. Используйте собственную конфигурацию DSH. Нет ссылки на сеанс рабочего стола, которую можно было бы открыть. DSH по умолчанию загружает журналы сеансов в DeepSeek, см. [его описание](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/reference/README.md).

<a id="section-54"></a>
### Доступ через браузер

Инструмент браузера устанавливается на компьютер, на котором работает Агент, и предоставляется конфигурацией инструмента или навыком проекта CLI. Плагин Кодекса запускает фоновый режим [`codex exec`](https://developers.openai.com/codex/noninteractive/); вы можете использовать настроенный [инструмент MCP](https://developers.openai.com/codex/mcp/). Тот факт, что настольное приложение может открыть веб-страницу, не означает, что фоновое приложение также может получить доступ к тому же браузеру.

Полные правила, сценарий вызова навыков и параметров Клода, вверяющего Кодекс, см. в [Шаблон передачи браузера](../examples/recipes/browser-handoff/README.md). Команды входа, цели и разрешенные операции настраиваются самостоятельно; веб-помощник возвращает доказательства и номер сессии, а основная задача отвечает за дела и поступления.

При наличии выделенного входа в браузере фактическая команда, режим соединения сеанса и разрешенные операции записываются в `prompt` или `skill` правила. Передаются только шаги веб-страницы, а также возвращается просмотренный контент, результаты операций и причины блокировки; основная задача отвечает за поступления бизнеса и среднего офиса. Портал браузера не является обязательным компонентом, а сервис не объединяет сценарии для определенного компьютера и не изменяет автоматически конфигурацию инструмента CLI.

Для задач, требующих принятия веб-страницы, следует использовать один и тот же метод фонового запуска для фактического открытия целевой страницы, проверки содержимого и продолжения сеанса. При нехватке доступных входов или необходимости восстановления соединения, входа и верификации самостоятельно, сохраняйте непринятые элементы и используйте существующий `ask` для ожидания восстановления; не пишите «не удалось запустить», чтобы инициировать перераспределение, и не рассматривайте HTTP-запросы как завершенное принятие веб-страницы.

<a id="section-64"></a>
## Плагин канала

Начните с [hello-channel/channel.ts](../examples/plugins/hello-channel/channel.ts). Он записывает карточки в файл и отвечает на них с помощью командной строки.

Асинхронная функция экспортируется по умолчанию, и параметром является `{ hub, options, log, signal }`; `options` происходит от `config.json`, за исключением ключа сервиса.

| позвонить | функция |
|---|---|
| `hub.nextCard(50)` | Долгий опрос для получения карты, карта не возвращается `{ card: null }` |
| `hub.delivered(id, version, ref)` | Отчет о доставке, сохранение номера внешнего сообщения |
| `hub.failed(id, version, error)` | Отправка отчета не удалась |
| `hub.answer(id, { choice, by, ref })` | Передать ответ; проверить автоответчика и исходное сообщение |

Если `ref` пуст, будет отправлено новое сообщение, а если есть значение, исходное сообщение будет обновлено; об этом будет сообщено только в том случае, если его невозможно обновить. Карты, о которых не сообщалось, будут перераспределены через одну минуту. `signal` завершает работу при прерывании; если функция возвращает или выдает ошибку до этого, она будет зарегистрирована и перезапущена через 30 секунд, поэтому она должна запускаться всегда. Плагин и сервис находятся в одном и том же процессе: необнаруженные ошибки только протоколируются, а выход промежуточной платформы не допускается.

Зарегистрируйте канал в `rules.json`, используйте `agent-autoloop key new channel cards` для получения ключа, затем поместите следующий элемент в `channels` `config.json` и перезапустите центр:

```json
{ "cards": { "use": "hello-channel", "key": "ключ канала", "file": "/tmp/cards.txt" } }
```

Канал, который может отозвать вызов, должен установить в правилах `answerers`. Если он не установлен, ответить может любой участник канала, `doctor` напомнит; канал, который может отправлять только текст, должен установить `links: true` и отправлять `card.link`. Тот, кто получит ссылку, сможет ответить на карточку.

Канал и сервис совместно используют процесс узла, и внешние вызовы должны ожидать асинхронно. Пользовательский запрос, отправка и обновление встроенного канала Feishu вызывают асинхронный вызов CLI, а сервис по-прежнему может получать события и тактовые сигналы во время отправки.

## Плагин событий

Начните с [hello-source/source.ts](../examples/plugins/hello-source/source.ts). Он проверяет HMAC-SHA256 в `x-shop-signature` и превращает заказ в событие.

Функция синхронизации экспортируется по умолчанию, и параметром является `{ headers, body, secret }`. Сначала проверьте подпись, а затем разберите исходный текст; верните массив событий, верните `[]`, если ничего не происходит, и выдайте исключение, если запрос отклонен. Плагин событий только преобразует, но не отправляет запросы.

Источник регистрации по адресу `rules.json`:

```json
{ "shop": { "name": "Магазин", "adapter": "hello-source" } }
```

Адрес запроса - `/v1/in/shop`; секрет - `AGENT_AUTOLOOP_SECRET_SHOP`, помещенный в `secrets.env` (имя источника преобразуется в верхний регистр, `-` заменяется на `_`, после изменения центр перезапускается), а правила не прописываются. Событие должно иметь стабильный `id` и легальный `type` и может включать `subject`, `summary`, `detail` и `link`. Верхний предел см. в [Протокол](protocol.md#section-74).

Когда источник может напрямую отправлять стандартный JSON, нет необходимости писать плагин, просто вызовите `POST /v1/events` с ключом источника.

<a id="section-105"></a>
## Права доступа: реальные ограничения

`access` транслируется плагином, а не системной песочницей, предоставляемой центром. Ниже показано поведение без дополнительного ослабления собственных разрешений.

| Плагин | `read` | `edit` | `full` |
|---|---|---|---|
| Кодекс | `read-only`: по умолчанию можно запускать оболочку, нельзя записывать файлы, команды не могут быть подключены к Интернету | `workspace-write`: может запускать оболочку, записывать рабочий каталог и временный каталог, команды по умолчанию не могут подключаться к Интернету | `danger-full-access`: Может записывать файлы, запускать оболочку, подключаться к Интернету, без одобрения |
| Клод Код | `plan`: может читать файлы и выполнять команды только для чтения; другие команды зависят от автоматического утверждения и местных правил | `acceptEdits`: разрешить редактирование файлов и общие операции с файлами в каталоге; любую оболочку или сеть по-прежнему необходимо разрешить | `bypassPermissions`: пропуск одобрения инструмента, дополнительная изоляция системы не требуется |
| Ремень DeepSeek | `read-only`: Запись файлов невозможна, чтение файлов и работа в сети не ограничены | `workspace-write`: Изменения команд и файлов ограничены рабочим каталогом и временным каталогом, чтение файлов и работа в сети не ограничены | `danger-full-access`: Без ограничений |
| АШП | Когда агент спросит, согласитесь прочитать и выполнить поиск | Затем согласитесь на правку в рабочем каталоге | Согласитесь на все операции, которые он просит |

Три передачи Кодекса были запущены с использованием подключаемых команд; DeepSeek Harness и Claude Code компилируются в соответствии с [DSH Document](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/reference/README.md) и [Официальным описанием разрешения](https://code.claude.com/docs/en/permission-modes) соответственно, без вызова модели для запуска. Ограничения командной сети Кодекса не совпадают с ограничениями управляемого поиска и MCP. Подробности см. в [Официальных инструкциях по песочнице](https://learn.chatgpt.com/docs/agent-approvals-security). Конфигурация пользовательского интерфейса командной строки может изменить вышеуказанные возможности; `read` не означает, что локальный ключ не может быть прочитан.

`access` ACP обрабатывает только операции, активно запрошенные Агентом. Спецификация позволяет агенту выполнять действия без запроса. Эту операцию нельзя остановить с помощью `access`, и она должна быть ограничена собственным режимом агента. Например, `env INITIAL_AGENT_MODE=read-only …` записывается как `command`. `model` и `effort` ACP не вступают в силу и должны быть установлены на самом агенте.

Шаблон сцены выбирает разрешения на основе этого: используйте `edit` для утренних отчетов для записи локальных файлов, используйте `edit` для проблем, чтобы изменить код и позволить фиксированной сети сценариев получать текст, и используйте `read` для сигналов тревоги, чтобы увидеть код и стек вызовов, прикрепленный к событию. `edit` используется для обработки отзывов и сводки Feishu, а `read` используется для устранения неполадок на веб-сайте; фиксированная проверка и сценарии чтения Feishu отвечают за работу сети, а агент сводки читает только полные снимки. `command` и фиксированные сценарии выполняются под локальной учетной записью и не подпадают под действие `access`.

## Проверка соответствия протоколу

Запустите существующие HTTP-проверки протокола в каталоге движка, используя временные данные и случайные порты:

```bash
node --disable-warning=ExperimentalWarning --test tests/conformance.test.ts
```

При проверке реализации других промежуточных платформ используйте `agent-autoloop conformance <тестовый адрес> --config <файл тестовых ключей>`. Формат файла см. в [Протокол](protocol.md#section-300). Он записывает события и карточки и запускает их только на специальном тестовом стенде.

Полный тест доступа к самому плагину см. в [tests/example-plugins.test.ts](../tests/example-plugins.test.ts). Вы также можете написать независимые процессы на других языках, см. [канал Curl/jq](../examples/channel.sh) и [Программа приема заказов](../examples/worker.sh).
