# Протокол

Система образует цикл между тремя видами подключений.

```text
Источники -- события --> Сервис <-- задания -- Исполнители -- Агент
                           |
                        карточки
                           |
                         Каналы <--> Владелец
                           |
                         ответы --> Сервис
```

**Ядро не выполняет исходящие подключения.**Источники событий, исполнители и каналы сами обращаются к сервису. Ядру не нужно знать, где они работают, на каком языке написаны и какому продукту принадлежат. Их внешние учетные данные остаются на стороне подключений. Для нового плагина достаточно уметь отправлять HTTP-запросы с JSON.

На одном компьютере одна команда запускает все части в одном процессе. Они используют тот же протокол. Для распределенного размещения настройте сетевой доступ и HTTPS; по умолчанию сервис слушает только loopback.**Общей веб-панели нет.**Управление доступно через CLI и каналы уведомлений. Отдельный клиент может использовать API владельца, перечисленный ниже. Страница одной карточки представляет собой форму без скриптов.

<a id="section-20"></a>
## Основные понятия

| Понятие | Значение |
|---|---|
|**Событие**| Факт из источника: ID, тип, объект, краткое описание, подробности и ссылка. Время по расписанию и ответ на карточку тоже создают события. |
|**Правило**| Доверенная запись в `rules.json`: какие события обрабатывать, каким агентом, в каком каталоге, с каким Skill и когда уведомлять владельца. |
|**Дело**| Работа по одному объекту в рамках правила. С делом связаны события, карточки, проверки и сессии. Без `parallel` все правило образует одно дело. |
|**Цикл**| Одно выполнение: получить события, передать результат и завершить процесс. Цикл заканчивается, а дело может продолжаться. |
|**Результат**| Последнее сообщение агента. Дополнительные действия сервиса записываются в структурированном блоке и применяются одной транзакцией при завершении цикла. |
|**Карточка**| Вопрос с вариантами ответа или уведомление. Ответ создает новое событие и продолжает дело. |

<a id="section-31"></a>
## Шесть принципов

1.**Внимание владельца ценно.**По умолчанию система работает тихо. Вопрос нужен, когда его требует правило или только владелец может устранить препятствие.
2.**Все является событием.**Внешняя система, расписание, повторная проверка и решение пользователя проходят общий путь обработки.
3.**Подключения приходят к ядру.**Ядро не делает внешних запросов. Учетные данные остаются там, где используются.
4.**Агент - это процесс.**Он получает подсказку и печатает последнее сообщение. Подходят CLI-агенты, скрипты и CI-процессы. Процесс, запускающий удаленную работу, должен дождаться ее фактического завершения.
5.**Цикл не ждет человека.**Агент записывает вопрос и завершает процесс. После ответа начинается новый цикл с продолжением прежней сессии, если оно возможно. Во время ожидания агент не расходует токены; состояние сохраняется после перезапуска.
6.**Инструкции задают правила.** Текст события не выбирает агента, каталог, Skill или права. Недоверенные заголовки и тексты находятся в файле данных, а не в подсказке. Это снижает риск инъекции в подсказку, но не устраняет его: агент все равно может прочитать чужой текст. Права нужно ограничивать отдельно.

<a id="section-40"></a>
## Правила

```jsonc
{
  "timezone": "Asia/Shanghai",                       // Часовой пояс, используемый для отсчета времени, и «сегодня», часовой пояс системы по умолчанию.
  "askFirst": ["Удаление данных", "Остановка сервиса", "расходы", "Отправка сообщений во внешний мир"],  // Только такие вещи Agent Сначала я спрошу тебя
  "sources":  { "shop": { "name": "shop" }, "github": { "name": "GitHub", "adapter": "github" } },
  "agents": {
    "claude": { "name": "Claude Code", "worker": "mac-mini", "use": "claude", "model": "…", "effort": "high", "access": "edit" },
    "cursor": { "name": "Cursor", "worker": "mac-mini", "use": "command", "command": ["agent", "-p", "--trust", "{prompt}"] }
  },
  "channels": { "feishu": { "name": "Feishu", "answerers": ["ou_xxx"] } },
  "rules": [{
    "name": "Обработка сигнала тревоги",
    "when": { "source": "shop", "types": ["alert.*"] },   // или { "cron": "0 9 * * *" }
    "to": "claude", "cwd": "~/code/shop", "skill": "run-ops", "prompt": "Согласно... обрабатывается один участок.",
    "group": "ops",                                        // Одна и та же группа используется по одному циклу за раз, а по умолчанию используется имя правила.
    "parallel": 3,                                         // После записи предметы делятся по объекту: один и тот же объект находится по одному циклу за раз, и эта группа имеет наибольшее количество 3 циклов; также действует ограничение исполнителя worker.capacity ограничение (по умолчанию 2）
    "resume": true,                                        // Новые события по той же теме следуют за предыдущим сеансом, и каждый раз по умолчанию открывается новый сеанс.
    "tell": "needed",                                      // always отправлять после каждого успешного цикла; не отправлять для NOTHING и FAILED/ needed Только при наличии карты (по умолчанию)/ never Отключите только уведомление в структурированного результата, а вопросы и собственные сигналы тревоги станции будут отправляться как обычно.
    "emits": { "source": "shop", "types": ["pr.*"] }      // Какие события можно отправлять в структурированного результата? Если не написано, то отправить нельзя.
  }],
  "elsewhere": [{ "name": "Еженедельная очистка", "source": "shop", "to": "claude", "cron": "0 6 * * 0", "where": "Claude Запланированные задачи приложения" }]
}
```

`elsewhere` - это задача, запуск которой запланирован в другом месте: промежуточная станция не запускает их, а указана только в `agent-autoloop status`. Когда они захотят вас найти, используйте `POST /v1/tell`. Если правило написано неверно, изменения в файле не вступят в силу. Старое правило продолжит действовать, и вам будет выдана карточка с указанием места ошибки.

Записано `resume`. В начале цикла, если предыдущий цикл дел завершен (в том числе нечего делать) и сеанс остался, то этот сеанс будет продолжен; сессия будет становиться все длиннее и длиннее, а токен и комиссия также будут соответственно увеличиваться. Открывайте новую сессию в таких ситуациях: последний цикл был остановлен (вами или постоянными неудачами), и тогда, вероятно, будет тот же результат; последний цикл проводил другой Агент; в последнем туре сессии не было. Когда `parallel` не написано, все правило - это одно дело, и все события связаны с одним сеансом; если событие не включает `subject`, оно также считается тем же. Ответы и должные отзывы по-прежнему будут возвращены в сеанс, когда был задан вопрос и назначена встреча, а переназначенные также останутся в своем сеансе.

Независимо от того, записан `resume` или нет, если в принимаемом диалоге есть другие циклы, которые не завершились, или нет новостей, или он все еще может выполняться, в этом цикле будет открыт новый диалог, и двум процессам не будет разрешено открыть один и тот же диалог; к нему все равно будет доведено содержание ответа и отзыва.

Задачи, поставленные в очередь и ожидающие повторной попытки, используют последний агент, каталог, слова приглашения и разрешения при их получении; если Агент изменен, сеанс старого Агента не будет принят. Заявленные задачи сохраняют конфигурацию задания и процедуры получения заказов, когда они были заявлены. Повторные заявки, пульсации, остановки и перезапуски не будут обновляться и заменяться согласно правилам. Вопросы, отнесенные к событию, не будут повторно разделены или объединены, а просмотр ответов и сроков выполнения вернется к вопросам на момент вопроса и согласия. То же самое произойдет, если правило позже будет удалено как `parallel`; разрешение на событие и способ уведомления в структурированного результата по-прежнему проверяются в соответствии с правилами на момент подачи.

<a id="section-74"></a>
## Источник: Превратите мир в событие

```
POST /v1/events                    Authorization: Bearer <ключ источника>
{ "id": "12:new", "type": "feedback.new", "subject": "#12", "summary": "…", "detail": "…", "link": "https://…" }
→ 200 { "event": 34, "duplicate": false, "routed": ["Обработка мнений"] }
```

- Требуются `id` и `type`. Один и тот же `id` из одного и того же источника записывается только один раз, поэтому источник может отправить его повторно.
- `subject` может быть только идентификаторами (буквы, цифры и `# . _ : / @ -`), `link` может быть только URL-адресами в чистом формате ASCII, поскольку они будут содержать слова-подсказки. `summary` и `detail` не вводят слова подсказки.
- События, не соответствующие правилам, также сохраняются и могут быть просмотрены `agent-autoloop status`.
- Верхний предел поля: `id` 200 символов, `subject` 100, `summary` 200, `detail` 4000, `link` 500, `type` 64 символа.

Три других способа входа - то же самое в центре:

- **Время**: Правило записывается `cron`. Если вы его пропустите (например, если компьютер закрыт), вы сможете наверстать упущенное только тогда, когда проснетесь. Повторяющееся время (летнее время) запускается только в первый раз, а несуществующее время пропускается.
-**Вебхук других людей**: `POST /v1/in/<источник>`. Когда источник настроен с помощью `adapter`, он передается функции в `plugins/<adapter>/source.ts` для проверки подписи и преобразования ее в события. Он только переводит и не отправляет запросы. Секрет для проверки подписи помещается в `AGENT_AUTOLOOP_SECRET_<источник>` `secrets.env` (имя источника преобразуется в верхний регистр, `-` заменяется на `_`, после изменения перезапускается центр), `rules.json` не вводится.
-**Опрос**: Нет необходимости подключаться к общедоступной сети, и жетоны не будут потрачены, если нет ничего нового. Правило периодически вызывает сценарий (также агент), и сценарий возвращает новое событие в `events` структурированного результата. `id` события должен быть стабильным, диапазон чтения может перекрываться, а сервис удалит дубликаты; сценарий должен переместить собственный курсор после передачи структурированного результата или вообще не покидать курсор.

Исходная задача или задача `elsewhere` может сообщить вам что-то напрямую (без обработки Агента):

```
POST /v1/tell    { "key": "weekly-44", "text": "…" }              Authorization: Bearer <ключ источника>
POST /v1/tell    { "task": "Еженедельная очистка", "key": "x", "text": "…" }   Authorization: Bearer <ключ исполнителя>
→ 200 { "card": 56, "duplicate": false }
```

<a id="section-101"></a>
## Агент: получить работу, работу, сдать структурированный результат

На каждом компьютере имеется исполнитель, которая подключается только к внешней среде. Одна исполнитель может обслуживать несколько Агентов.

```
GET /v1/work?claim=<номер полученного задания>&wait=50&running=7,8&capacity=1    Authorization: Bearer <ключ исполнителя>
→ 200 { "job": null | Job, "cancel": [7] }
```

- Когда жизни нет, подождите не более `wait` секунд и немедленно вернитесь, как только появится новая жизнь. `running` - это то, что работает на руке, а также сердцебиение. `capacity=0` только сообщает о регистрации и не получает работы.
- Когда у вас есть работа, вы можете попросить ее и отменить каждую секунду. Сердцебиение записывается в журнал не чаще одного раза в минуту, а по количеству циклов в раздаче записывается только одна запись; то же самое относится и к канальным картам. Таким образом, `seenAt` из `/v1/state` может произойти менее чем на одну минуту раньше, чем в последний раз, а «нет отчета в течение 5 минут» и «нет соединения в течение 10 минут» также могут быть оценены менее чем за минуту до этого; `online` оставляет запас в эту минуту и ​​считается онлайновым в течение 3 минут после записи.
- Ответ потерян. Используйте тот же `claim` еще раз и вернитесь к тому же заданию.
- `cancel` необходимо остановить. Программа приема заказов сначала посылает сигнал остановки всей группе процессов. Если через 10 секунд еще выполняются процессы, они будут принудительно завершены. Только после подтверждения отсутствия в группе живых процессов `outcome: "cancelled"` сдается, и дело освобождается. Перезапуск процесса приема заказов во время периода остановки также продолжает этот шаг. Возврат `failed` для останавливаемого цикла считается остановленным и не будет повторяться.

```jsonc
// Job：все данные одного цикла.token Это действительно только для данного выполнения данного цикла.
{
  "run": 12, "token": "…", "attempt": 1,
  "rule": { "name": "Обработка сигнала тревоги", "cwd": "~/code/shop", "skill": "run-ops", "prompt": "Согласно... Процессу." },
  "agent": { "id": "claude", "name": "Claude Code", "use": "claude", "model": "…", "effort": "high", "access": "edit" },
  "session": null,       // Старайтесь максимально следить за разговором: это последний раз при переназначении, ответ приходит из цикла вопросов, а правила прописаны. resume содержит сессию предыдущего цикла этого дела. Если продолжить ее нельзя, создается новая; это только оптимизация
  "askFirst": ["Удаление данных", "…"],
  "context": {           // Исполнитель записывает это в файл для агента Agent，все это данные
    "events":  [{ "id", "source", "sourceName", "type", "subject", "summary", "detail", "link", "receivedAt" }],
    "answers": [{ "card", "title", "options", "choice", "text", "about", "by", "at" }],  // решения, которые нужно продолжить в этом цикле
    "timers":  [{ "key", "about", "at" }],                                               // проверки, срок которых наступил в этом цикле
    "waiting": [{ "key", "about", "at" }],                                               // будущие проверки этого дела
    "open":    [{ "card", "title", "text", "at" }],                                      // Карты из того же источника и группы, которые еще не завершены
    "decided": [{ "card", "title", "choice", "at" }]                                     // решения этого дела, действующие только в прежнем контексте
  }
}
```

```jsonc
// Result
{
  "outcome": "done" | "nothing" | "failed" | "cancelled",
  "summary": "краткий итог", "error": "причина неудачного цикла", "session": "…",
  "usage": { "input": 0, "output": 0, "cached": 0, "cost": 0 },
  // Ниже приводится структурированный результат, которая вступает в силу один раз в транзакции.
  "ask":     [{ "title", "text", "options": ["…", "…"], "recommend": 0, "about": "Контекст для продолжения работы", "key": "стабильное имя решения" }],
  "notice":  [{ "title", "text", "key", "fyi": true }],
  "resolve": [{ "card": 3, "reason": "Где было проверено, что проблема решена?" }],
  "later":   [{ "key": "…", "at": "2026-11-05T09:00:00+08:00", "about": "Что тогда проверять" }, { "key": "…", "cancel": true }],
  "events":  [{ "id", "type", "subject", "summary", "detail", "link" }]
}
```

- Результат может быть воспроизведен: ответ потерян, тот же токен снова отправлен с тем же содержимым и получено то же подтверждение; если содержимое отличается, возвращается 409.
- `failed` будет перераспределен, поэтому он содержит только `notice`, а остальные не вступят в силу; цикл платежей, который я хочу остановить, `failed`, не будет перераспределен, и `notice` не вступит в силу.
- Когда вам необходимо восстановить соединение, вход в систему или проверку личности, используйте `done`, чтобы завершить этот цикл и передать `ask`, но не передавайте `failed`. `done` указывает на конец этого цикла, и незавершенные дела будут сопровождаться картой. Это не означает, что веб-страница была принята. Если в том же блоке уже есть карта `open`, вопрос не будет повторяться, и `later` не будет использоваться для регулярных повторных попыток; обзор того же блока в `waiting` будет отменен с `cancel`. Сохраните завершенное дело, `about` и запишите только оставшиеся шаги после восстановления.
- `usage` Об использовании этого исполнения сообщает программа приема приказа, включая перезапись структурированного результата этого исполнения; каждый элемент можно опустить: `input`, `output`, `cached` - количество токенов, а `cost` - доллар США. Сервис суммирует сообщаемые значения каждого выполнения в одном и том же цикле, и повторные отправки не будут снова оплачиваться; поля, о которых не сообщается, остаются по умолчанию и не должны быть установлены на ноль. `agent-autoloop status` Подведите итоги циклов, которые завершились сегодня и за последние 7 дней, в соответствии со временем завершения, и запишите количество циклов, о которых не было сообщено правдиво. При обновлении старые поступления не будут пересчитываться, а совокупное значение, которое было перезаписано до обновления, не будет автоматически компенсироваться.
- Некоторые агенты предоставляют только совокупную стоимость сеанса (токен Кодекса, плату за код Клода). Программа приема заказов перед этим запуском вычитает накопительное значение и затем сообщает об этом, поэтому текущее количество всегда здесь; эти элементы не будут сообщаться для продолжающихся подключений без записей. Подробности см. в разделе [Описание плагина](plugins.md#section-25).
- Диапазон `key` `ask` заключается в следующем: та же самая карта `key` больше не будет выдаваться, если она все еще открыта. Повторный запрос после выключения - это новый вопрос.
- `notice` может опционально заполнять логическое поле `fyi`: `true` означает «только уведомлять». Когда карта создается, это `closed`. Он по-прежнему будет доставлен в течение 24 часов после создания. Фейшу отображает серую карточку без кнопки «обработано»; `open` не будет участвовать в последующих циклах, и нажатие не будет генерировать событие ответа. При пропуске или заполнении `false` сохраняется исходное поведение: уведомление имеет кнопку «обработано», а закрыть дело можно также по `resolve`. Он закрывается сразу после создания, поэтому тот же `key` будет выпущен снова в следующем цикле записи; один и тот же цикл повторной попытки будет выполнен только один раз. Старые структурированного результата не затрагиваются, а правила молчания для `ask` и `tell: "never"` остаются неизменными. Старый мидл не знает этого поля и отклонит всю структурированный результат: когда мидл и исполнитель развертываются отдельно, то в первую очередь будет обновлен мидл.
- `resolve` можно комбинировать только с картами из того же источника, той же группы и картами, существовавшими до этого цикла заявок, а те, которые находятся за пределами поля, записываются в `rejected`, что не повлияет на результаты этого цикла.
- В данном случае речь идет о диапазоне `key` `later`. Повторное написание того же `key` означает изменение времени.
- Источник `events` определяется `emits` правила, и получение не может быть изменено.

<a id="section-166"></a>
### Агенту нужно сделать только одну вещь

Программа приема заказов передает слово подсказки Агенту, и последнее сообщение от Агента является квитанцией:

````
Первая строка - краткий итог. Для временной ошибки с автоматическим повтором: «FAILED: причина». Для препятствия, устраняемого только владельцем: «Требуется ваше действие: причина» и вопрос через ask，Если работы нет, напишите «NOTHING: причина». Иначе завершите цикл; продолжение дела задается структурированным результатом.

```agent-autoloop
{ "ask": [ … ], "notice": [ … ], "resolve": [ … ], "later": [ … ], "events": [ … ] }
```
````

Кодовые блоки являются необязательными. Агенту не нужно ничего устанавливать или подключаться к сервису, поэтому агенты в песочнице и облаке также могут подключаться.

Если структурированный результат написана неправильно, дело не будет переделано: исполнитель продолжит исходный сеанс и позволит переписать последнее сообщение только один раз, максимум два; Агенты без сеансов (например, `command`) не будут перезаписываться и будут напрямую следовать приведенному ниже предложению. Если вы по-прежнему не можете его прочитать или процесс переписывания не запускается, сообщает об ошибке, истекает время ожидания или нет вывода, просто сохраните окончание первой строки исходного делового сообщения, аннулируйте структурированный результат ​​и нажмите карточку, чтобы сообщить вам, где находится исходный текст (вывод каждого цикла будет сохраняться в течение 14 дней после окончания этого цикла); непополнение чека не превратит завершенное дело в автоматический повтор.

<a id="section-182"></a>
### Подберите нового агента

Напишите строку в правиле, подойдет любая команда, которая может напечатать последнее сообщение, даже если код выхода не равен 0, она не запустится:

```json
{ "name": "Hermes", "worker": "mac-mini", "use": "command", "command": ["hermes", "chat", "-Q", "-q", "{prompt}"] }
```

Если вы хотите продолжить сеанс, открыть ссылку сеанса и получить статистику использования, просто напишите файл по адресу `plugins/<имя>/agent.ts` (см. `plugins/claude/agent.ts`):

```ts
export default {
  command: (run) => [...],                                         // командная строка этого цикла,run.resume сессия, которую нужно продолжить
  read: (output) => ({ text, session, usage, finished, started }), // Прочитать последнее сообщение и разговор из вывода
  link: (session) => "…",                                          // Необязательно: откройте ссылку для этого сеанса.
};
```

`started` указывает, что Агент принял этот цикл слов подсказки, и его необходимо взять с собой независимо от того, завершен ли он, произошла ли ошибка или процесс завершился. При этом, если в этом цикле произойдет ошибка, он будет считаться неудавшимся, а исходная сессия останется на сервиса и будет переназначена; без него сбой старого сеанса будет рассматриваться как сбой подключения, и будет открыт новый сеанс для повторного запуска слова подсказки. `finished` означает, что этот цикл действительно завершен, и он будет остановлен, если не выйдет через 30 секунд; он не учитывается, если фоновая задача не завершилась и агент должен вернуться, чтобы продолжить.

Три файла специального плагина `access` преобразуются в соответствующие разрешения CLI: `read` доступен только для чтения, `edit` только меняет рабочий каталог (по умолчанию), а `full` имеет полное разрешение и не требует одобрения. Только чтение не означает, что ключ не может быть прочитан. Чтобы изолировать ключ, используйте системную учетную запись или контейнер. `command` только передает параметры команды и не ограничивает разрешения для какой-либо программы.

Браузер предоставляется операционной средой Агента. Кодекс использует фон `codex exec` и не может предполагать, что подключение к браузеру настольного приложения доступно автоматически; используйте инструменты браузера, фактически доступные в этом цикле, или запись, явно настроенную правилами или навыками. Портал только обрабатывает шаги веб-страницы и продолжает собственный сеанс, а основная задача по-прежнему отвечает за бизнес и поступления. Средняя платформа не оснащена мостом между браузерами и не устанавливает и не авторизует инструменты браузера; информацию о разрешении доступа см. в [инструкции к плагину](plugins.md#section-54).

## Канал: отправить вам открытку.

Канал - это небольшая программа, которая соединяется с внешним миром.

```
GET /v1/cards/next?wait=50    Authorization: Bearer <ключ канала>
→ 200 { "card": null | Card }

// Card：текущее представление карточки; после создания меняется только состояние, а не содержимое
{ "id": 56, "version": 2, "ref": null, "kind": "ask", "state": "open",
  "title": "…", "text": "…", "options": ["…", "…"], "recommend": 0,
  "choice": null, "answer": null, "by": null, "result": null, "link": null }
```

- `ref` Если он пуст, отправьте новый; если он не пуст, просто измените его на текущий. Если это невозможно изменить, просто сообщите об этом напрямую.
- Отправить отчет: `POST /v1/cards/56/delivered { "version": 2, "ref": "om_xxx" }`. Если отчета не будет, я сообщу вам об этом через минуту.**Для платформ, поддерживающих идемпотентные ключи, при отправке новых сообщений используется только номер карты, без версии** (Если Feishu не может изменить закончившуюся карту, отправьте другую, и у этой будет только версия). Дедупликация не может быть гарантирована, если платформа ее не поддерживает, а шаблон веб-перехватчика может быть повторно отправлен после потери отчета.
- Невозможно отправить: `POST /v1/cards/56/failed { "version": 2, "error": "…" }`. Первый раз отправил, попробовал еще раз с все более и более длительными интервалами, а потом через час сдался (карта все еще была открыта, `agent-autoloop status` ее видел); оно не засчитывается, если канал не пришел его забрать.
- Карты, которые были разыграны до доставки, больше не будут вас беспокоить; Уведомления только для уведомлений `fyi` по-прежнему будут доставляться в течение 24 часов с момента создания.
- Вы нажали: `POST /v1/cards/56/answer { "choice": 1, "by": "ou_xxx", "ref": "om_xxx" }`. Засчитывается только первый раз, `by` должен находиться в `answerers` этого канала, а `ref` должен соответствовать доставленному. В обычных уведомлениях есть кнопка «Обработано», нажмите на нее, чтобы закрыть дело; Вы также можете написать объяснение обработки с помощью `text`, а `answer`, внесенный в карту, когда корпус закрыт, можно увидеть на поверхности карты и `/v1/state`. Только уведомление. Уведомление `fyi` не имеет кнопки.

Самый маленький канал имеет всего дюжину линий: прием карточек, отправка текста и `link`, а также отчетность. `link` оснащен только каналом `"links": true`, а остальные каналы - `null`. Откроется обычная страница формы, на которой не выполняются скрипты. На ней весь текст и кнопки этой карточки. Ответить на вопрос сможет тот, кто получит ссылку. Она действительна в течение 7 дней с момента создания карты. По истечении срока действия содержимое карты больше не будет отображаться. Он подходит для групповых роботов и электронных писем, которые могут отправлять только текст. Каналы, которые могут отправлять кнопки и снимать вызовы (например, Feishu), используют кнопки, а личность проверяется платформой, что безопаснее. При использовании на компьютере `link` является локальным адресом и не может быть открыт на мобильном телефоне. Если вы хотите использовать мобильный телефон, установите центр на машину с адресом общедоступной сети и настройте `publicUrl`.

## Я: Посмотрите на ситуацию в целом, ответьте, закройте дело, остановитесь.

```
GET  /v1/state              Authorization: Bearer <ключ владельца>
→ 200 { "totals", "cards", "recentCards", "agents", "channels", "sources", "lines", "elsewhere", "runs", "nextBefore", "hasMore", "unrouted", "spending", "now", "timezone" }

POST /v1/cards/56/answer    { "choice": 1 } или { "text": "Другой ответ" }
POST /v1/cards/56/resolve   { "reason": "Нет необходимости принимать решение, потому что..." }
POST /v1/runs/12/cancel     {}
```

`agent-autoloop status`, `answer`, `resolve`, `stop` являются этими запросами. `/v1/state` выдает за раз последние 60 патронов, а `?before=<nextBefore>` переворачивает более ранние.

`spending.today` и `spending.week` из `/v1/state` не зависят от пейджинговой связи и суммируются согласно времени завершения сегодняшнего дня и последних 7 × 24 часов в обычном часовом поясе. Каждый элемент включает `rounds`, `tokens`, `cost`, `missingTokens` и `missingCost`. Последние два пункта - это количество циклов, по которым не была сообщена сумма заявки; циклы, отмененные до начала, не засчитываются. Старые поля запроса и ответа остаются неизменными, и старый клиент может игнорировать новые поля; новую версию `status` нужно обновлять вместе с мидл офисом, а история уже не читается постранично для расчета стоимости.

Установка и удаление не изменяют протокол HTTP. `agent-autoloop --version` отображает версию и представление; `agent-autoloop uninstall` удаляет собственные программы, ссылки и сервисы после подтверждения и всегда сохраняет правила, ключи и записи; `--yes` только пропускает подтверждение.

## Что происходит, когда он выходит из строя?

| Что случилось | Что произойдет |
|---|---|
| Источник дважды опубликовал одно и то же событие | Запомни это только один раз |
| Ответ на запрос о работе потерян | Тот же `claim` вернулся на ту же работу |
| Ответ о результате передачи потерян | Повтор получает то же подтверждение |
| Агент не удалось запустить | Переносится через 5 минут, каждый раз увеличивается вдвое, до 1 часа; события одного и того же периода за период объединяются в этот цикл; говорю вам третий раз подряд; нет повторной попытки 10-й раз подряд, этот цикл записывается как `cancelled` и отправляется карточка уведомления, а новые события во время выполнения учитываются как еще один цикл; когда этот цикл заканчивается или останавливается, карточка с надписью, что он попытается еще раз, закрывается |
| Мне нужно восстановить подключение браузера, вход или верификацию | Этот цикл завершен, сохраненные выполненные дела и предметы, подлежащие принятию, ответы с помощью карточек вопросов и т. д. не будут переназначаться автоматически |
| Исходный сеанс невозможно подключить | Откройте новый сеанс и продолжайте использовать файл данных |
| Подключился к исходному сеансу, но прервался посередине | Он не был завершен, поэтому остался в исходной сессии и был переназначен в соответствии с указанным выше ритмом, без открытия новой сессии и переделывания дел |
| Агент выходит из строя или процесс исчезает, но в той же группе процессов все еще есть живые процессы | Сначала отправьте сигнал остановки этой группе процессов и принудительно завершите его, если он все еще существует через 10 секунд. Результат будет сдан тогда, когда в группе не будет живых процессов; перезапустите программу приема заказов во время остановки и продолжите этот шаг. Код выхода равен 0 и не перемещается. `ps` Когда вы не можете запустить, вы не можете видеть, что находится в группе, поэтому вы можете отправить результаты напрямую. Инструмент недоступен, если он открывает собственную группу процессов. CLI Codex и Claude Code запускают инструменты таким образом, поэтому их инструменты могут работать одновременно с перенесенным циклом |
| Неправильное написание чека | Только переписать структурированный результат, а не переделывать дела; Агентская структурированный результат без сеанса недействительна, нажмите карту |
| Плагин агента не может прочитать собственный вывод | Если он все еще работает, он продолжит работать; после завершения или завершения процесса он не будет завершен, останется в исходном сеансе и будет перенесен |
| Программа или канал приема заказов остановлены, либо плагин имеет ошибку не перехватывает | Сохраните журнал и перезапустите через 30 секунд; средний офис и другие части в обычном состоянии |
| Другие процессы слишком долго занимают базу данных | Не делайте этого, пока не истечет этот раз, повторите попытку через 5 секунд, и центр не выйдет; файл правил, который за этот период был написан плохо, также об этом вам скажет |
| Невозможно записать лог (выходной канал сломан, диск переполнен) | Процесс завершается и подтягивается системной службой |
| Перезапустить программу приема заказов | Работающий агент не затронут, вернитесь и продолжите мониторинг |
| Программа приема заказов подключена к сети, но уже 5 минут не сообщается о наличии определенного цикла | Отметьте это как «неопределенное», отпустите эту группу и расскажите вам; результаты, представленные позже, все равно будут приняты |
| Вся исполнитель исчезла | Держите задания и не отпускайте, и я вам скажу раз в 10 минут; после закрытия карты эти вакансии больше не будут напоминаться, и я не буду говорить о новых работах, пока не появятся новые работы. Когда вы вернетесь, карта закроется автоматически. Я скажу тебе в следующий раз, когда больше тебя не увижу |
| Перезапуск сервиса | Всё в SQLite, все автоматически переподключатся |
| Время пропущено | Просыпайтесь и узнавайте только последние новости |
| Вы щелкнули дважды или щелкнули оба одновременно | Засчитывается только первый раз |
| После задания вопроса проблема решится сама собой | После последующей проверки Агента она закроется в `resolve`, а карточка автоматически изменится на «Решать не нужно» |
| Правило написано неправильно | Продолжайте действовать по старым правилам и подскажите, где ошибка |
| Правила были удалены или переименованы | Цикл, который еще не востребован, и цикл, который не завершен, будут записаны как `cancelled` и больше не будут распространяться, а также будет отправлена ​​карточка с уведомлением; те, кто уже бегает, получат результаты в обычном режиме после завершения забега |
| Файл правил был удален, перемещен или не может быть прочитан | Старое правило продолжит действовать, и я скажу вам один раз; верните его обратно и продолжайте использовать. Новая платформа, на которой ни разу не загружались правила, не читается и не запускается |

Это система «хотя бы один раз»: Агент может быть вызван дважды, поэтому действия с побочными эффектами в Навыке должны сначала проверить текущий статус.

## Журнал и уверенность

Каждый раз, когда принятый ввод генерирует пакет фактов, ничего не изменилось (повторяющиеся события, контрольные сигналы менее одной минуты с момента последнего раза) не генерируются; `commit` завершает оценку, добавляет журнал и позволяет `evolve` обновлять представление в той же транзакции SQLite WAL + FULL и отвечает только после завершения отправки. Версии правил, хэши ключей, заявки, структурированного результата и ответы - все это хранится в журнале; в журнале никогда не сохраняются круглые жетоны, жетоны связи с картами или центральные главные ключи. Главный ключ сохраняется оболочкой в ​​локальном файле, а круглый токен и ссылка на карту создаются отдельно с помощью HMAC. Если претензия повторится, токен все равно будет перевыпущен. Предыдущий немедленно станет недействительным, и существующее поведение сохранится.

`decide(view, input, now, environment)` не меняет входящий вид и ввод. `evolve(view, facts)` - единственный постоянный автор проекций; часы, файлы правил, случайный материал, сеть и один таймер предоставляются оболочкой. Факты включают версию, серийный номер, время, тип и нормализованные изменения записей, а при воспроизведении правила не повторяются. Представления считываются по требованию через индексы SQLite; только это изменение сохраняется после одного решения, вся таблица не копируется, и вся история не хранится в JavaScript. Строка правила является самой большой, и ее необходимо запрашивать в каждом цикле очереди, поэтому представление анализируется только один раз; новые факты - это новые взгляды, а старые правила читаться не будут. Журналы, прогнозы, курсоры журналов, нумерованные верхние водяные знаки и производные индексы представляются вместе; удаление записей не приводит к повторному использованию их номеров. Откройте проекцию непосредственно при обычном запуске. Оболочка вычисляет отпечаток формата на основе файла (`kernel/evolve.ts`, `kernel/credentials.ts`) и главного ключа, определяющего содержимое хранилища. Другие изменения файлов не учитываются. Представление запроса перестраивается при каждом запуске. Когда в старой версии нет курсора или отпечаток пальца не совпадает, журнал считывается по одному в той же транзакции, а проекция и индекс перестраиваются. Новые материалы, отправленные за этот период, не могут быть перезаписаны, а журнал не считывается в память сразу. Первое обновление может потребовать ожидания восстановления; старые факты не изменяются, и миграция данных не требуется. Моделирование реализуется с использованием того же набора прогнозов и суждений, а база данных размещается в памяти.

Уровень трансляции запроса узла остается в пределах 50 строк; файлы, соединения SQLite, прослушиватели и таймеры также предоставляются оболочкой.

`GET /v1/stream?after=42` принимает только мой собственный ключ и возвращает SSE: `id` - это порядковый номер журнала, `event: fact` и `data` - это JSON факта. Если журнал отключен, используйте `Last-Event-ID` или `after`, чтобы продолжить со следующего; читать весь лог с 0, отправлять его по одному в зависимости от скорости чтения абонента и не кэшировать все логи заранее. Подписчикам не отправляются хэши ключей или учетные данные возможностей.

`GET /v1/runs/42/why` принимает только ключ человека и возвращает факты, относящиеся к текущему циклу событий, версию правила каждого выполнения, структурированный результат, структурированный результат ​​и ответ карты. Командная строка `agent-autoloop why 42` использует тот же интерфейс, а время отображается как `MM-DD HH:mm:ss` в соответствии с местным часовым поясом. По умолчанию отображается событие, версия правила, получатель, время начала и окончания, сеанс, структурированный результат, ответ и временная шкала продолжения циклов, а текст правила не печатается; `agent-autoloop why 42 --json` выводит исходные факты. Запросы объяснения находят факты путем индексации записей с порядковыми номерами журнала. Эти интерфейсы наследуют мои права доступа. Когда внутренние ответы и синхронизированные события сталкиваются с существующими номерами, добавляются суффиксы, чтобы сохранить уникальность источника и номера и не перезаписывать источник события.

## Согласованность и повторяемость

Вход для плагина унифицирован как `plugins/<имя>/agent.ts`, `channel.ts` или `source.ts`. Сначала найдите каталог установки, а затем найдите встроенный каталог движка. `agent-autoloop add <git адрес>` Клонируйте хранилище плагинов в `plugins/<имя репозитория>` в каталоге установки. Файл импорта помещается непосредственно в корневой каталог хранилища. Он не будет обновляться автоматически и сценарий установки не будет выполнен. Плагин представляет собой доверенный код, установленный мной, и событие не может указать путь к плагину.

Событие принимает необязательный `hops`, неотрицательное безопасное целое число, которое по умолчанию равно 0. Событие получения вынуждено использовать максимальное количество переходов для всех событий в этом цикле плюс 1; ответ на вопрос и более поздние сроки продолжают первоначальную глубину. События, превышающие 8, по-прежнему записываются, но не отправляются, и генерируются уведомления; повторные отправки не дублируют уведомления. Это ограничение цепочки обработки внутри платформы: новые события, исходящие непосредственно из внешних источников, могут начинаться с 0. Если в старом журнале нет переходов, читайте его как 0.

`DELETE /v1/keys/<source|worker|channel|owner>/<имя>` принимает только персональные ключи; имя передается в соответствии с кодировкой URL-адреса и возвращается `{ok:true, changed}`: если удаляемый ключ не существует, `changed` имеет значение false, и факт не добавляется. `agent-autoloop key remove <тип> <имя>` вызывает работающую промежуточную платформу, удаляет длинный опрос, который немедленно просыпается и отклоняет ключ, и закрывает подписку на журнал. Заявленный цикл будет по-прежнему отправляться с независимыми жетонами цикла.

`protocol/schema.json` использует JSON Schema 2020-12 для определения форматов событий, квитанций, задач, карточек и журналов. `agent-autoloop conformance <тестовый адрес> --config <файл>` использует настоящий HTTP; файл содержит `keys` (четыре тестовых ключа источника, рабочего, канала и владельца), `eventType`, который может соответствовать правилам тестирования, и `answerer`, разрешенный каналом. Правило должно иметь возможность передавать источник и тип программе приема заказов, `parallel` должно быть не менее 2, а канал должен ограничивать количество ответчиков. Проверки записываются в события и карточки и выполняются только на специальном тестовом стенде; один и тот же испытательный стенд может проверяться непрерывно. Формат подписи каждого источника проверяется тестом соответствующего плагина.

Верхний предел текста рассчитывается в соответствии с кодовыми точками Unicode: `text` ответа на карточке имеет максимум 4000 символов, `by` имеет максимум 500 символов, `ref` имеет максимум 500 символов, а номер сообщения, сообщаемый каналом, имеет максимум 500 символов. `usage` должен быть численно неотрицательным и конечным объектом, а не массивом; `later.at` должен быть датой и временем ISO реальной даты с `Z` или смещением часового пояса. Перед выполнением структурированный результат должна быть проверена в целом.

`npm test` содержит 200 000 шагов моделирования начального числа 24301, а также все 8 последовательностей действий двух программ приема заказов, двух исходных событий и одной карты вопросов. Моделирование меняется на независимый сценарий каждые 128 шагов. Неисправность останавливается и работа завершается до окончания каждого сценария; инварианты и полное воспроизведение журнала проверяются для каждого перехода состояний. Запланированное событие инициируется таблицей реального срока действия, и после восстановления убедитесь, что не осталось задач с истекшим сроком действия. Это доказывает, что эти ограниченные сценарии не означают, что пространство состояний любого размера исчерпано. Индивидуальное воспроизведение: `node sim/random.ts 24301 200000`, `node sim/enumerate.ts`.

`npm run test:nightly` выполняет 1000 реальных SIGKILL процессов, 31 мутацию исполняемого ядра и проверки производительности. В случае сбоев используйте настоящий SQLite WAL + FULL для проверки подтвержденного порядкового номера, целостности, просмотра, воспроизведения и повторной отправки; он обнаруживает выход процесса и не имитирует полное отключение электропитания машины. Если какая-либо мутация пропущена, это будет считаться неудачей. Имя будет выведено напрямую, и синтаксические ошибки не смогут его обнаружить. CI регулярно выполняет принудительное уничтожение и мутацию каждый день. Бюджет проверки производительности устанавливается в соответствии с указанным выше компьютером и выполняется только локально. `node sim/crash.ts 1000 12648430` и `node sim/mutate.ts` могут воспроизводиться отдельно.

Проверка правильности моделирования должна пройти; скорость моделирования является лишь наблюдательным показателем эффективности разработки. Проверка производительности использует запись HTTP поочередно, а ответ поступает только после завершения транзакции. RSS в режиме ожидания и RSS при подключении измеряются отдельно; см. `scripts/metrics.ts` для реализации проверки и README для фактических измеренных чисел. Большой исторический объем (результаты см. в [Измерение исторического роста](#section-381)) используйте `node scripts/history.ts 1000 10000 100000` для проверки реального бизнеса, ответа HTTP, медленной подписки на журналы, повторной попытки принудительного уничтожения и полной реконструкции; Каждый сценарий включает в себя два цикла задач, вопросов, доставки, ответов и запланированных проверок, а также каждую отправку WAL + FULL. Запрос проходит через настоящий HTTP, и каждый тип операции и сводка состояния измеряются 30 раз, чтобы получить среднее значение; О непрерывной записи, простое и загрузке памяти сообщается отдельно, а сборщик мусора не запускается вручную.

Накладные расходы при очень глубокой очереди измеряются индивидуально с помощью `BENCH_QUEUE=5000 node scripts/benchmark.ts --busy`: правило около 4,4 КБ, ожидание 1000 длинных опросов, очередь 5000 циклов (`BENCH_QUEUE` можно изменить), сообщается о заблокированных пульсах p50 и p99, CPU каждого пульса, сколько фактов записывается за этот период и медиана полученных событий, задания полученные, достигнутые результаты и неполученные задания. `npm run benchmark` также содержит этот предмет.

### АСР и МСР

`use: "acp"` взаимодействует с `command: ["некоторый ACP программа", "Параметры запуска"]` для использования stdio ACP v1. Агент ACP, используемый в правиле, должен быть записан как `command`. Сначала инициализируется мост, а затем создается или продолжается старый сеанс: если агент объявляет `loadSession`, он будет использовать `session/load`, а если он объявляет только `sessionCapabilities.resume`, он будет использовать `session/resume`. История, воспроизводимая во время загрузки, не учитывается в качестве этого цикла ответов, а отражение и выходные данные инструмента не попадают в структурированный результат. Когда слово-подсказка отправлено, цикл начинается, и если он будет прерван после этого, он останется в исходном сеансе и будет переназначен. Когда старый сеанс возобновляется, половина работы может быть выполнена в прошлый раз. Только если Агент явно отклоняет сеанс (возвращается ошибка или восстановление не поддерживается), можно открыть новый сеанс; если программа не может запуститься, возникает ошибка инициализации или загрузка прерывается на полпути, исходный сеанс будет оставлен для перепланирования. Даже если сессия открывается другой программой (неправильный `data.reason` - `thread_active_writer`), это не считается отказом: этот цикл не считается успешным, поскольку Агент сам останется в исходной сессии и через некоторое время отправит ее повторно. Третья карта подряд будет содержать это предложение, которое подскажет вам, что следует закрыть. Все остальные ошибки считаются отклоненными без просмотра кода ошибки: официальный адаптер Кодекса возвращает -32603 для сеанса, которого на самом деле не существует. Полными считаются только `end_turn` и последнее текстовое сообщение: если есть `messageId`, то сообщение будет разделено в соответствии с ним. Если нет времени на размышления, вызов инструментов и завершенные или неудачные обновления инструментов, они будут считаться границами. Если цикл не завершен, мостик сразу объяснит причину. Если Агент не уйдет через 30 секунд, он остановится вместе с группой процессов. Сообщения обрамляются только разрывами строк, а строки, которые невозможно прочитать, не считаются успешными в этом цикле. Номер сеанса передается в центр на хранение. Нет декларации о чтении и записи файлов, возможностях терминала или интерактивного входа в систему. Агент использует свои собственные инструменты; при входе в систему он сначала использует собственную командную строку для входа.

Для разрешений выбираются только одноразовые опции: `read` разрешает структурированное чтение и поиск, `edit` разрешает редактирование в рабочем каталоге (проверяйте символические ссылки, а ссылки, которые не могут найти цель, засчитываются вне каталога), `full` разрешает другие операции. Если запрос разрешения содержит только номер вызова инструмента, он будет оцениваться в соответствии с типом и путем, указанными перед этим вызовом, и запрошенное поле имеет приоритет. Отменить без предоставления опции. Разрешения зависят от соответствия агента требованиям ACP и не обеспечивают дополнительную изоляцию системы; спецификация позволяет агенту выполнять действия без запроса. Эту операцию нельзя остановить с помощью `access`, и она должна быть ограничена собственным режимом агента. Единственный вариант отклонения (`reject_once`), предоставляемый официальным адаптером Кодекса, - это `cancel`. Если вы выберете его, весь цикл закончится `stopReason: cancelled`. Оно не считается успешным и будет передано центром. Вот так возвращается запрос на запуск команд под файлами `read` и `edit`. Поэтому, когда агент должен выполнить команду, он выдаст `full`. Или используйте собственный шаблон. `model` и `effort` недействительны. Основа проверки: [Инициализация](https://agentclientprotocol.com/protocol/v1/initialization), [Сессия](https://agentclientprotocol.com/protocol/v1/session-setup), [Разрешения инструмента](https://agentclientprotocol.com/protocol/v1/tool-calls).

`agent-autoloop mcp` предоставляет стандартный MCP, фиксированно поддерживает версию [2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) и не поддерживает протокол отсутствия установления связи от 28 июля 2026 г. Это инструменты `status`, `why`, `answer`, `resolve`, `stop`, `emit` и `tell`; инструменты отображаются в соответствии с человеком или исходным ключом, который уже есть у машины. Он вызывает тот же HTTP-интерфейс и не меняет базу данных напрямую; ключ остается на локальной машине `config.json`. Клиент MCP устанавливает для программы значение `node`, в качестве параметров - абсолютные пути к движку `bin/agent-autoloop.ts` и `mcp`, а среду - для указания `AGENT_AUTOLOOP_HOME`. Стандартный вывод записывает только JSON-RPC. Сообщения обрамляются только разрывами строк; каждый вызов инструмента отвечает независимо, а медленные вызовы не блокируют `ping`. Он не различает звонящего, а записывает его по человеку (`answer` записывается как человек, `emit` не имеет слоя). Не настраивайте пользовательскую конфигурацию CLI, запускаемую программой приема заказов, иначе цикл ответит на свою карту.

### Шаблон канала и пример командной строки

Конфигурация `config.json` канала Webhook использует `use: "webhook"`, `url` и `platform`, а последний может быть опционально `dingtalk`, `wecom`, `slack` и `discord`. Если платформа не написана, `body` можно использовать для настройки шаблона, а `{text}` в строке заменяется содержимым карты. Четыре шаблона сравниваются с официальными документами: [DingTalk](https://open.dingtalk.com/document/orgapp/custom-bot-send-message-type), [Qiwei](https://developer.work.weixin.qq.com/document/path/91770), [Slack](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/), [Discord](https://discord.com/developers/docs/resources/webhook#execute-webhook). DingTalk и Qiwei проверяют ответ `errcode`, Slack проверяет `ok`; Discord запрещает упоминания по тексту. Карты, превышающие размер Qiwei 2048 байт или Discord 2000 слов, сообщат об ошибке без сокращения ссылки на вопрос или ответ. Сам Webhook не имеет идемпотентной гарантии. Сообщение может быть отправлено повторно, если оно было успешно отправлено, но отчет потерян.

Уведомление на рабочем столе `desktop` - это канал, открытый по умолчанию для новых установок: `osascript` для macOS и `notify-send` для Linux. Заголовок уведомления - «Агент задал вам вопрос», а текст - заголовок карточки и «Запустить статус автоцикла агента для просмотра»; текст передается через параметры после `--` и не прописывается в скрипт. Уведомитель не вызывается при отсутствии графического сеанса, сообщает `skipped-<номер карточки>`, и не прерывается повторно; карточки по-прежнему можно просматривать и отвечать на них через командную строку. Если существует графический сеанс, но команда уведомления не существует или не удалась, сообщается `failed`, и центр организует повторную попытку. Обновления карты только сообщаются и не всплывают повторно.

`examples/worker.sh` и `examples/channel.sh` используют только встроенные команды оболочки, curl и jq. Перед запуском установите `AGENT_AUTOLOOP_URL` и `AGENT_AUTOLOOP_KEY`; `AGENT_AUTOLOOP_ONCE=1` можно запросить только один раз. Пример получения заказа возвращает JSON в формате `AGENT_AUTOLOOP_RECEIPT`, и возврат завершается по умолчанию; пример канала выводит карту на терминал, а затем сообщает о доставке. Это короткие примеры задач, которые не подходят для длинных задач; длинные задачи используют такт, остановку и возобновление `worker/`. `tests/examples.test.ts` фактически запускает два сценария, охватывающие клавиши вопроса, доставки, ответа, продолжения и ошибки, на временном промежуточном этапе, который проходит проверку согласованности протокола.

<a id="section-336"></a>
## Шаблон бизнес-сценария

`examples/recipes/` предоставляет семь наборов сценариев. Обработка обратной связи, проверка веб-сайта, еженедельный отчет Feishu и бизнес-сводка по умолчанию используют личный приватный чат Feishu и `Asia/Shanghai`; все они представляют собой комбинации существующих правил, каналов и `command` без добавления полей протокола или основных знаний о продукте.

Источник обратной связи отвечает только за пробуждение того же самого вопроса, а текущий бизнес-статус и авторизация повторно считываются из доверенного интерфейса. При проверке веб-сайта в качестве записей о сбоях используются карточки уведомлений об исключениях, которые не были закрыты в соответствии с этим правилом: уведомления и события устранения неполадок будут отправлены при первом сбое, скрытые сбои продолжатся, восстановление будет закрыто и возникнут параллельные события восстановления; если карта по-прежнему выходит из строя после ручного закрытия невосстановленной карты, об этом будет сообщено повторно. Feishu собирает полные показания, а затем записывает одновременные события частного снимка, а сводка проверяет номер снимка. Старые события не используют новые данные; сборник и аннотация сериализуются в одной группе. В агрегацию включаются только данные, читаемые личностью человека, а невидимые данные не считаются непредставленными.

Шаблон передачи обслуживания браузера представляет собой вызов параметра основной задачи установленного портала без добавления нового протокола или драйвера браузера. Доверенная конфигурация имеет фиксированные команды, цели и разрешенные операции, а при продлении используется номер сеанса Кодекса, фактически возвращаемый порталом; веб-контент и внешние события не могут изменить эти диапазоны. Когда соединение, вход или проверка заблокированы, основная задача `ask` завершит текущий цикл. После ответа он продолжит только оставшиеся шаги веб-страницы. Браузерный помощник не будет повторно делегировать полномочия или закрывать дело самостоятельно.

Сценарии проверки и сводки Feishu проверяются с использованием локального поддельного HTTP и поддельного CLI Feishu, без вызова реальных бизнес-данных или отправки реальных сообщений. Публичные образцы не содержат внутренних адресов, номеров счетов или деловых записей; данные, замененные пользователями, не должны передаваться в хранилище. Структура и обязанности каналов остаются неизменными, а схема архитектуры соответствует существующему трехпортовому протоколу.

## Доставить плагин

Доставка представляет собой обычный процесс агента `plugins/delivery`, который не распознается ядром. В проекте по-прежнему используется `ops/delivery.json`, теги по-прежнему `deliver`, `deliver-attended`, `deliver-review`, `ask-owner`, а статус отправки по-прежнему `delivery`. Статус проверки по умолчанию равен `agent-review` и изменяется `review.status`; команда изменена `review.command`. Для настройки форматов, правил и примеров доставки см. [Руководство по настройке](../skills/agent-autoloop/SKILL.md#section-97).

Источник дается только событиям, а команды хранения и выполнения фиксируются правилами сервиса. Встроенный `poll.ts` считывает ожидающие теги и генерирует стабильные номера событий на основе «репозитория, предмета, записи тега, текущей отправки» без сохранения курсора; когда определенный элемент не может прочитать запись тега, этот раздел записывается как 0, что не влияет на другие элементы. Никакие теги (так же, как и объединенные), закрытые и необъединенные, форк или неосновные цели не запускают доставку. Каждый PR имеет одну материю, а параллелизм контролируется правилом `parallel` и возможностями исполнители; в случае сбоя процесса будут использоваться 5-минутные повторные попытки и непрерывные уведомления об ошибках промежуточной платформы, без создания дополнительных очередей, слотов, счетчиков неудач или служб уведомлений.

| Шаги | Должен удовлетворить |
|---|---|
| Чтение настроек | Используйте фиксированную отправку основного текста для этого цикла проверки, чтобы прочитать настройки проекта и просмотреть ключевые моменты, а не читать версию в PR; после пересылки основного, перечитайте цикл |
| Синхронизация | PR уже содержит основной; если отсутствует, запросите синхронизацию GitHub. Подождите, пока не появится синхронизированное представление, прежде чем продолжить этот цикл. Если он не появится в течение 15 минут, цикл завершится и центр повторит попытку |
| Обзор | Голые различия между объектами и текстом в Git; проверяются только собственные материалы ветки, изменения, которые полностью сливаются с основной, исключаются, а разрешение конфликтов сохраняется; обычные внутренние документы могут пропускать модель; файлы, которые Git считает двоичными, также сохраняются как текстовые снимки; когда в ветке есть три или более родительских материалов, изменения нельзя увидеть в обзоре, и о проблеме сообщается напрямую, что требует ее изменения на обычное слияние; разница в одном представлении превышает 32 МБ. Во время рецензирования его даже просмотреть нельзя. Вы также можете сообщить о проблеме напрямую. PR, которые не используют эту модель, не будут затронуты. При записи снимка замените NUL-байты, иначе весь файл не сможет найти содержимое |
| Процесс проверки | Не выгружайте код PR в рабочее дерево (checkout) и не выполняйте его код, тесты, конфигурацию или hooks; Кодекс по умолчанию игнорирует пользовательскую конфигурацию и память и читает только независимые снимки |
| Полная проверка | Черновик сначала переводится в состояние готовности, а перед переносом записывается последняя проверка, и принимаются только более новые (тип триггера рабочего процесса должен иметь `ready_for_review`); принимается только последний отправленный в данный момент pull_request. И рабочий процесс, и указанное задание завершены и успешны, черновики или пропущенные задания не учитываются; каждый элемент матричного задания (с именем `check (ubuntu-latest)`) должен быть успешным |

| Автоматическое слияние и потеря ответа | Сначала отключите существующее автоматическое слияние и прочитайте подтверждение; если ответ на объединение утерян, сначала проверьте, был ли он объединен, и не отправляйте его снова вслепую; если очистка тега не удалась, прочитайте еще раз, чтобы подтвердить, был ли он удален; объединенный PR окончательно удалит `deliver`, а объединенный PR окончательно удалит `deliver-review`. Если удалена только часть, повторную попытку можно продолжить, а заявки на подачу заявок, которые только проверяются, не будут объединены |
| Релиз | Подождите, пока Ship, который охватывает отправку слияния, будет успешным, а затем проверьте исправную версию; работоспособный HTTP 200 не может устранить сбой поставки или не был завершен |
| Последующие выпуски | Старые поставки могут быть завершены, если новая версия защищена и действительно доступна в сети; завершенные поставки не будут регрессированы из-за последующих неудачных релизов |

`deliver-review` Проверка завершается, и этикетка доставки удаляется, что не означает, что она была проверена, объединена или подключена к сети; добавление этой метки во время ожидания проверки остановится только на проверке перед слиянием и не будет записывать статус проверки, позволяющий слияние. Если во время проверки обнаруживается проблема, как `delivery`, так и статус проверки будут записаны как сбой, и проблема будет возвращена; карточки уведомлений разделены по подаче, и вновь присланные задачи не будут поглощены, если предыдущая не будет закрыта; для `deliver-attended` не будет создана дополнительная карточка уведомления. Отправления со статусом проверки «Провал» не будут проверены или изменены, пока тег все еще существует. Цикл завершится сразу и не будет пересматриваться до тех пор, пока не будет подана новая заявка. Эта запись зависит от статуса проверки, поскольку при неудачном цикле ошибка будет записана в `delivery`. `deliver` снимается в ожидании чека. Этот цикл окончен. `delivery` пишется как успех, а в описании указано, что он отозван, а не объединен и не выпущен. Для обычной проблемы `ask-owner` в карточку проблемы превращается только читаемый текст, блок кода и локальный путь удаляются, а метка удаляется после ответа. Не публикуйте комментарии на GitHub, не создавайте журнал многоцикловых проверок в описании PR и не поддерживайте использование «обработанного» текста для исключения обнаруженных проблем; новые материалы будут рассмотрены повторно.

Объединенный PR с тегом `deliver` будет продолжать напрямую отслеживать судно и проверку работоспособности. Те, у кого удален тег, больше не будут отслеживаться и статус не будет написан; те, которые были объединены другими в период проверки, также будут отслеживаться, а обнаруженные в ходе проверки проблемы будут записываться в структурированный результат; в случае сбоя отслеживания этот цикл будет записан как «Не удалось выполнить», и уведомления об этих проблемах будут отправлены одновременно, и центр повторит попытку, как обычно. По умолчанию максимальное время отслеживания составляет 30 минут, а время ожидания будет передано в мидл-офис для повторной попытки; проекты без настроек работоспособности будут явно сообщать, что завершено только слияние. Сравнение объема выпуска **Вся разница между работоспособной версией и целевой фиксацией**: можно пропустить только обычные внутренние изменения документа, исполняемые биты, символические ссылки, переименование на внешние пути и неизвестную историю - все это необходимо выпустить; только последующие изменения документа не могут позволить пропустить незавершенные выпуски кода. Когда интерфейс работоспособности сообщает короткий номер отправки, сначала измените его на полный номер из GitHub. Если вы не можете его изменить, он будет опубликован.

Ship использует `plugins/delivery/action.yml` этого репозитория двигателей, и проект фиксируется до полной подачи после выпуска. Действие выводит только `release` и `superseded`, а в проекте есть этап выпуска, который запускается на основе выходных данных. Он разделяет объем и оценку работоспособности `project.ts` с процессом доставки и не дублирует инструменты в проекте в течение длительного времени.

Общие URL-адреса работоспособности поддерживают только HTTPS. `--test-local-health` должен быть передан явно во время тестирования, а действие также требует, чтобы `test-local-health: 'true'` принимал `http://127.0.0.1`; другие HTTP-адреса не принимаются. Правила слияния GitHub устанавливаются сопровождающими проекта.

## Версия и совместимость

Номер версии написан только на теге (`v1.2.3`), и никакие файлы не вводятся. `agent-autoloop --version` считывает тег текущей отправки и отображает «Неопубликовано» для неопубликованных материалов.

| Самое влиятельное изменение в этой версии | Как изменить номер версии |
|---|---|
| Только решите проблему | Добавьте единицу к третьей цифре: 1.1.1 → 1.1.2 |
| Добавьте новые возможности или измените поведение по умолчанию, старое использование все еще может работать | Добавьте единицу ко второй цифре: 1.1.1 → 1.2.0 |
| Если старое использование не будет изменено, оно не будет работать | Добавьте единицу в первую позицию: 1.1.1 → 2.0.0 |

Старое использование относится к ним:

- Путь, значение поля и аутентификация интерфейса `/v1`;
- Соглашение о плагине (`plugins/<имя>/{agent,channel,source}.ts`);
- `rules.json`；
- Команды и параметры, записанные в документе;
- Договор поставки (`ops/delivery.json`, четыре тега, статус `delivery`);
- Данные, оставшиеся после старой версии, могут быть использованы в новой версии.

Внутренние коды, поля, не записанные в документе, и текст подсказки не учитываются. Добавление новых полей не считается уничтожением, поэтому плагины и клиенты должны игнорировать незнакомые поля. Чтобы удалить что-то, сначала пометьте это как устаревшее и отправьте вторую версию, а затем удалите это в следующей первой версии.

`/v1` учитывается отдельно: он меняется только в том случае, если HTTP-интерфейс несовместим. Программное обеспечение версии 2.0 не соответствует протоколу `/v2`. Отправленная версия не будет изменена. Если возникнут какие-либо проблемы, будет отправлен следующий номер.

Пакет изменений будет опубликован в тот же день после их завершения; сбои, потеря данных, проблемы безопасности и исправления, которые невозможно установить, будут опубликованы в тот же день; остальные будут публиковаться по вторникам каждую неделю. Те, которые меняют только документацию, тестирование и CI, не будут выпущены. Для серьезных изменений сначала может быть выпущена пробная версия (`v1.2.0-rc.1`), но установка и `update` не будут ее устанавливать.
