# Предварительная проверка безопасности

Дата: 5 ноября 2026 года. Исходный проект: [KKKKhazix/agent-autoloop](https://github.com/KKKKhazix/agent-autoloop). Проверяемая база: `a3b77bf26c0b98bb9eb1edd10ede2e3c13bfdd5d`.

## Вывод

Не считать проект безопасным для автономной работы с важными данными без дополнительной изоляции. В просмотренных участках не обнаружено подтвержденной скрытой отправки учетных данных, но проверка не доказывает отсутствие вредоносного поведения или уязвимостей во всем проекте и его зависимостях. Полного аудита каждого форка и проверки эксплуатации на Linux/macOS пока нет.

База для адаптации - исходный проект с сохранением истории и лицензии MIT. Изменения сторонних форков автоматически не включались.

## Метод и границы

Изучены устройство проекта, правила для разработчиков, начало протокола, загрузка плагинов, ключи и HTTP-доступ, карточки, адаптеры GitHub/GitLab, права Codex/Claude и механизм ревью доставки. Выполнено сравнение доступных прямых форков через GitHub API с фиксированным исходным коммитом. Сравнение истории и поиск опасных конструкций не заменяют построчную проверку всех изменений. Отсутствующие в ответах API фрагменты больших diff требуют отдельного чтения.

Код реального автономного сервиса, установщик, доставка в production и плагины форков не запускались. Зависимости разработки установлены через `npm ci --ignore-scripts`. Тесты используют временные каталоги, локальные сервисы и фиктивные программы; проверки с реальными агентами отдельно не выполнялись.

## Основные риски

| Приоритет | Наблюдение | Доказательство и практическое следствие |
|---|---|---|
| Высокий | `askFirst` не является системным запретом | `worker/contract.ts` передает перечень действий в подсказке. Выполняемая агентом команда не проходит отдельный универсальный шлюз подтверждения. Ошибка модели или prompt injection может привести к действию без вопроса. |
| Высокий | Режим `full` существенно расширяет доступ | `plugins/codex/agent.ts`: `danger-full-access`, `approval_policy="never"`; `plugins/claude/agent.ts`: `bypassPermissions`. Не включать для недоверенных событий. |
| Высокий | Плагины являются исполняемым доверенным кодом | `host/plugins.ts` делает динамический `import`; плагин из каталога пользователя имеет приоритет над встроенным. Клонирование плагина не означает его проверку. |
| Высокий | Изоляция обычного пользователя недостаточна для секретов | `access: read` не обещает запрет чтения всех файлов аккаунта. Выделить отдельный системный аккаунт или контейнер без рабочих ключей. |
| Средний | Ссылка на карточку передает полномочие | В `kernel/http.ts` ссылка действует семь суток. Любой получатель ссылки может ответить на эту карточку. Не публиковать ссылки и не отправлять их в общие каналы. |
| Средний | Резервные копии содержат секреты | Копируются `master.key`, конфигурация и `secrets.env`. Ограничить доступ и шифровать хранилище резервных копий. |
| Средний | Сохраненная сессия удерживает недоверенные данные | `resume` сохраняет контекст между циклами. Данные прежнего события могут повлиять на последующие решения модели. |
| Средний | Установка и обновления зависят от доверия к GitHub и автору | `install.sh` получает код из Git, `cli/update.ts` следует исходному remote. Команда загрузки с передачей в shell исполняет полученный установщик. Для эксплуатации нужен проверенный фиксированный коммит. |

Это преимущественно границы доверия и эксплуатационные риски, а не утверждение о найденной удаленной уязвимости в исходном проекте.

## Подтвержденные защитные механизмы

- `host/http.ts` по умолчанию слушает `127.0.0.1`.
- `kernel/credentials.ts` разделяет назначения токенов через HMAC-SHA256, хранит хеши обычных ключей и использует `timingSafeEqual`.
- `plugins/github/source.ts` проверяет HMAC подпись тела webhook, `plugins/gitlab/source.ts` проверяет секретный токен. Пустой секрет не разрешает запрос.
- `kernel/http.ts` ограничивает размер тела запроса и проверяет тип ключа для операций.
- `kernel/card-page.ts` экранирует текст, использует CSP с запретом скриптов, `no-store` и `no-referrer`. Открытие ссылки само по себе не отправляет ответ.
- `plugins/delivery/review.ts` формирует текстовый снимок Git без checkout кода PR; стандартная команда ревью включает read-only sandbox и отключение пользовательской конфигурации и памяти. Пользовательская команда ревью требует отдельной проверки.

## Проверки

- Использован отдельный Node `v24.22.2`, системный Node 22 не заменялся.
- `npm ci --ignore-scripts`: установлено 24 пакета, npm audit сообщил 0 известных уязвимостей для этого lockfile на момент запуска. Это не проверка логики приложения.
- `npm run typecheck`: успешно.
- Первоначальный `format:check` выявил CRLF в Windows checkout. Окончания строк исходников возвращены к LF без изменения их содержимого. Повторный `npm run format:check` прошел; `.gitattributes` закрепляет LF для кода, JSON, YAML и shell.
- Полный набор тестов не прошел в текущей Windows-среде: ошибки ACP/файловых прав, поиска `codex` и платформенных сценариев. Его выполнение было остановлено. Совместимость и безопасность Windows этим запуском не подтверждены.
- Отдельный запуск HTTP/GitLab/ядра показал успешные проверки разделения ключей, карточек и webhook; общий успешный результат этого запуска пока не подтвержден. Нельзя выдавать отдельные зеленые тесты за полностью пройденный набор.
- Изолированный повтор `tests/gitlab.test.ts` завершился успешно: 4 теста, 4 пройдено, 0 ошибок.

## До рабочего выпуска

Завершить русификацию по [перечню](localization-ru.md), запустить полный набор тестов на поддерживаемой ОС, проверить обновление и восстановление, затем выполнить реальный цикл в изолированной среде. Начальные правила должны использовать минимальные права и тестовые данные. Права `full`, сторонние плагины, публичные webhook и автоматическую доставку включать только после отдельного рассмотрения их полномочий.
