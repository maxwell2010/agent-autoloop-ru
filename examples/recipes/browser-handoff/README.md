# Клод поручает Codex управлять браузером

Основная задача отвечает за бизнес, Кодекс только обрабатывает веб-страницы, а основная задача завершается после получения доказательств. Поддерживает последующие операции в одном сеансе браузера; когда человеку необходимо восстановить соединение, войти в систему или подтвердить действие, завершить цикл, вернуть карту Фейшу и дождаться ответа человека, прежде чем продолжить.

<a id="section-5"></a>
## Как включить

1. Скопируйте этот каталог в `~/.agent-autoloop/work/browser-handoff/`, который доступен для чтения только мне. Поместите `SKILL.md` в `~/.claude/skills/claude-browser-handoff/`. Когда основная задача меняется на Кодекс, Навык помещается в `~/.codex/skills/claude-browser-handoff/`, а правило изменяется на `use`; значение по умолчанию по-прежнему остается основной задачей Клода.
2. Настройте запись Кодекса, которая уже может использовать браузер, и заполните ее фактический массив команд в `browser.json.command`. Если `codex-browser` уже существует локально, укажите его абсолютный путь. `/path/to/browser-entry` - заполнитель; этот шаблон не устанавливает мост браузера, не изменяет внутреннюю базу данных настольного приложения и не копирует псевдоним SSH компьютера, файл модели или логику очистки процесса Chrome.
3. Заполните целевой URL-адрес, элементы проверки и разрешенные операции в `browser.json`. По умолчанию принимается `example.com` только для чтения, форма не отправляется, сообщение не отправляется. `allowedActions` - это область задачи Агента, а не изолированная программная среда системы. Объем операций должен определяться лицом или соглашением о доверенном обслуживании проекта и не может быть автоматически создан на основе внешних событий. Учетные данные для входа не помещаются в конфигурацию; Фактический URL-адрес компании и номер сеанса остаются в личном каталоге.
4. Объединить `sources`, `agents`, `channels`, `rules` в `rules.json`, заменить компьютер-получатель заказов, каталог и персональный open_id Фейшу; повторно используйте существующий канал и ключ Feishu и не открывайте новый мониторинг событий. Запустите `agent-autoloop check`.
5. Права доступа: `edit`. Это представляет собой только режим `acceptEdits` Клода, и нет никакой гарантии, что любая команда ввода браузера может быть выполнена. Используйте тот же фоновый метод, что и исполнитель, для проверки вызывающего органа; если вход не одобрен, настройте его в соответствии с существующей авторизацией и не меняйте его автоматически на `full`. Область действия помощника браузера и разрешения учетной записи также не предоставляются в этом поле.

<a id="section-13"></a>
## Соглашение о доступе через браузер

Вход принимает полный параметр задачи: `browser-entry "Веб-задача"`; продолжение принимает `browser-entry --resume <сессия ID> "Последующие задания"`. Возвращает фактическое свидетельство страницы, результаты операций и блокировку с указанием `[Codex сессия ID：фактический номер]` в конце. При использовании других записей должны быть предусмотрены те же соглашения о вызове и возврате.

`handoff.ts` отвечает только за передачу доверенной конфигурации в качестве параметра, сохраняя стандартный вывод, код ошибки и выхода; не повторять попытку и не считать «команду запущенной» завершенной. Существующие записи могут выполняться на компьютере, где расположен браузер, либо передаваться самостоятельно через SSH; пользователь должен сначала убедиться, что компьютер может получить доступ к целевому URL-адресу, и что удаленный браузер не может рассматривать локальный `localhost` как компьютер, принимающий заказы.

Серверная часть Кодекса [`codex exec`](https://developers.openai.com/codex/noninteractive/) может использовать свой собственный сконфигурированный [инструмент MCP](https://developers.openai.com/codex/mcp/), но нельзя сделать вывод, что он имеет соединение Chrome для настольного приложения. Просто установить Codex CLI недостаточно, выбранный портал должен быть фактически принят; этот шаблон является методом передачи задач, а не драйвером подключения браузера.

<a id="section-21"></a>
## Проверка перед активацией

Запуск в каталоге шаблона:

```bash
node handoff.ts browser.json
node handoff.ts browser.json --resume <Фактический сеанс, возвращенный на предыдущем шаге-ID>
```

Впервые проверьте фактический заголовок страницы, видимый основной заголовок и ссылку; правдиво запишите страницу, если нет текстового основного заголовка. Вторая проверка продолжается в исходном сеансе; после завершения существующие доказательства должны быть возвращены, а операция не должна повторяться для продления. Убедитесь, что исходные вкладки сохраняются, а новые, созданные вами, закрываются. Затем вызовите тот же сценарий с помощью метода фонового запуска Клода, чтобы убедиться, что он действительно получил доказательства и номер сеанса. HTTP-запросы не заменяют принятие страницы.

В специальном тесте станция отправляет событие стабильного номера `browser.verify` источнику `browser-tasks` для запуска; тот же запрос передается повторно для сохранения `id`, например:

```json
{"id":"browser-check-1","type":"browser.verify","subject":"site-check","summary":"Проверить настроенную веб-страницу"}
```

События не несут в себе команды входа, целевые пути или разрешения. Для блоков, требующих личного управления, используйте `ask` в Навыке, чтобы завершить текущий цикл; не будет повторной передачи, если карты уже есть, и пересмотра на следующем приеме. После ответа я просто продолжаю выполнять незавершенные шаги веб-страницы.

<a id="section-40"></a>
## Внедрение в существующий бизнес

Такие задачи, как обработка обратной связи и проверка веб-сайта, могут напрямую загружать этот навык: поместите `handoff.ts` в этот каталог, а `browser.json`, настроенный мной, в его частный рабочий каталог и укажите местоположение в доверенных основных правилах задач, поэтому нет необходимости создавать набор расписаний. Основная задача сначала завершает все, что можно сделать, затем поручает веб-странице проверить и, наконец, возвращает структурированный результат ​​в мидл-офис; браузерный помощник не делегирует повторно или самостоятельно не закрывает дело.

Автоматически проверять использование поддельных порталов браузера для проверки передачи параметров, возобновления сеанса и распространения ошибок без запуска настоящего Chrome. Образец публикации содержит только образцы URL-адресов и заполнителей; каждому пользователю по-прежнему необходимо проверить подключение к браузеру и разрешения на вызовы Клода.
