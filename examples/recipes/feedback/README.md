# Обработка обратной связи с пользователем

Обратная связь запускает обслуживание, за дополнением следует обработка, а ответ делается после онлайн-проверки. Данные выборки полностью вымышлены; он не привязан к определенной системе обратной связи и не создает собственную библиотеку заказов на работу.

<a id="section-5"></a>
## Как включить

1. Поместите `SKILL.md` в `~/.codex/skills/handle-feedback/`; Код Клода в `~/.claude/skills/handle-feedback/`.
2. Объединить `sources`, `agents`, `channels` и `rules` из `rules.json` в существующие правила и сохранить существующие записи; используйте `Asia/Shanghai` для часового пояса. Измените `worker` на компьютер, принимающий заказы, а `cwd` на домашний каталог вашего проекта.
3. Запишите истинное чтение обратной связи, претензию (если она есть в исходной системе), проверку версии, обратную запись статуса и ввод ответа, а также существующие этапы доставки и онлайн-приемки в руководстве по обслуживанию **на проекте**main. Инструмент использует существующий CLI или MCP и не помещает команды и пути к хранилищу в события. Шаблон не угадает ваш интерфейс.
4. Права доступа: `edit`. Разрешен ремонт в утвержденных каталогах; Оболочка Кодекса по умолчанию не может подключиться к Интернету. Чтение обратной связи, PR и доставка требуют реально работающих настроенных инструментов; локальная модификация не равна выпуску. Нажмите [Описание разрешения](../../../docs/plugins.md#section-105), чтобы проверить фоновую операционную среду, и она не изменится автоматически на `full`.
5. Запустите `agent-autoloop check`. Используйте специальный источник тестов для подачи вымышленного события ниже, чтобы проверить задания, вопросы и ответы, прежде чем получать реальные отзывы.

<a id="section-13"></a>
## Как бизнес-система отправляет события?

Используя настроенный ключ источника, источник должен называться `feedback`. Следующая команда выполняется в этом каталоге шаблонов; `FEEDBACK_KEY` считывает данные из собственного управления учетными данными и не записывает в файлы или историю оболочки.

```bash
curl --fail-with-body http://127.0.0.1:3350/v1/events \
  -H "Authorization: Bearer $FEEDBACK_KEY" \
  -H 'Content-Type: application/json' \
  --data-binary @event.json
```

`feedback.new` используется для добавления новых веществ, а `feedback.followup` используется для добавок. Одна и та же обратная связь всегда использует один и тот же `subject`; каждое реальное изменение использует уникальный и стабильный `id` (например, номер отзыва плюс версия), а исходный номер сохраняется для повторной отправки. Пример `event.json` не является реальным рабочим заданием, которое можно обработать напрямую. Прочитанная запись должна быть настроена перед запуском; по умолчанию вам будет предложено заполнить запись. Источник отправляет только необходимую информацию, но не отправляет контактную информацию, токены доступа, списки клиентов или полный текст журналов.

Исходное событие не может быть одобрено от имени человека: вопросу будет присвоен приоритет в центре `ask`, и ответ активирует исходное дело. Если существующая бизнес-система сама отвечает за вопросы и ответы на них, решение о проверке личности исходной системы должно использоваться для настройки собственных событий продления; не создавайте две карты одновременно.

По умолчанию каждый элемент обратной связи представляет собой один элемент, максимум 3 элемента параллельно; объем заказа по-прежнему контролируется исходной конфигурацией. Прежде чем отправлять исходящий ответ, сначала подтвердите получателя и полный текст; если есть четкое разрешение, его можно выполнить напрямую. Если ответ не получен, будет отправлен только ответ, а завершенный выпуск не будет переделан.

<a id="section-30"></a>
## Уведомление Фейшу

Правило по умолчанию регистрирует канал `feishu`. Замените `ou_REPLACE_ME` на свой open_id; добавьте `user` этого человека и существующий ключ канала в `channels.feishu`, у которого уже есть `config.json`. Повторно используйте уже работающий канал Feishu и не открывайте другой канал мониторинга. Если вы еще не подключились, нажмите [Конфигурация канала](../../../skills/agent-autoloop/SKILL.md#section-76) для завершения; при настройке новых ключей или разрешений сначала получите разрешение.

Используйте личную идентификацию для чтения деловой информации и информируйте об использовании идентификации робота. По умолчанию оно отправляется только этому человеку; сервис раздаст карту всем каналам, на которые она настроена, и нет функции индивидуального выбора получателей по правилам. Для задач, содержащих личную информацию, вам следует использовать платформу, которая позволяет вам общаться только в частном порядке и не вмешиваться в общие групповые каналы. Не отправляйте в репозиторий ключи, фактические open_ids, токены таблиц или бизнес-данные.
