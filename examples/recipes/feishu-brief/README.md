# Еженедельный отчет Feishu и бизнес-резюме

Прочитайте отчеты с личным авторитетом, сравните таблицы проекта, организуйте прогресс и вопросы, требующие координации. По умолчанию указанный отчет и текущий статус указанной формы за последние семь дней считываются в 18:00 по пекинскому времени в воскресенье; Агент вызывается только после полного прочтения, а полный черновик сохраняется на локальной машине. Фейшу дает мне краткое изложение без деликатных подробностей.

<a id="section-5"></a>
## Как включить

1. Скопируйте этот каталог в `~/.agent-autoloop/work/feishu-brief/`, установите права доступа к каталогу `0700` и не помещайте его в репозиторий Git. Оба правила выполняются последовательно с использованием одного и того же компьютера, одного и того же `cwd` и одного и того же `group`, чтения и сопоставления.
2. Поместите `SKILL.md` в `~/.codex/skills/feishu-brief/`; Код Клода в `~/.claude/skills/feishu-brief/`.
3. Установите `lark-cli`, войдя в систему под своей учетной записью, сначала просмотрите `lark-cli api --help` и `lark-cli base +record-list --help` и убедитесь, что команды в шаблоне поддерживаются. Используются только существующие авторизации, а токены доступа не сохраняются и не экспортируются в скрипт.
4. Изменить `sources.json`: `reportRule` - точное имя существующего правила отчетности, `reportUsers` - open_id человека, которого необходимо суммировать и который имеет право на просмотр; `tables` заполняет свой собственный токен многомерной формы, идентификатор таблицы, исходную ссылку и необходимое имя поля. Заполните пустой массив без таблицы. Идентификаторы заполнителей нельзя использовать напрямую, а шаблон не будет создавать таблицы или расширять разрешения.
5. Объединить правила `sources`, `agents`, `channels`, `rules`, заменить компьютер заказа и путь; используйте `Asia/Shanghai` для часового пояса. Права доступа: `edit`, сводка. Агенту необходимо только читать данные и писать рукописи; Чтение по сети завершается фиксированным скриптом, который выполняет только команды чтения.
6. Запустите `agent-autoloop check`. Используйте поддельный интерфейс командной строки в специальном центре тестирования, чтобы проверить сбор, распространение сводки, вопросы и продление после неудачного входа в систему, а затем включите свои собственные правила синхронизации.

<a id="section-14"></a>
## Чтение и сохранение диапазона

Интерфейс отчетов - `POST /open-apis/report/v1/tasks/query`, который представляет собой операцию запроса, а требуемые полномочия - `report:task:readonly`. `--as user` используется для всех показаний, и принимаются только отчеты, инициированные и полученные пользователем, а затем фильтруются по человеку, правилу и времени; личность робота не будет доступна для получения дополнительных данных. Спецификацию интерфейса см. в [Задача запроса и отчета Feishu](https://open.feishu.cn/document/server-docs/report-v1/task/query.md). Не видеть чей-то отчет не значит, что он его не подавал. Прикрепленные изображения не будут загружены.

Форма использует `base +record-list`, считывает только указанные поля и проверяет нумерацию страниц с помощью файлов NDJSON и манифестов. Он не завершен до `has_more=false`; изменения межстраничной версии сообщат об ошибке, и часть данных нельзя назвать полной сводкой. Не переписывать формы, OKR или отчеты. Записи таблицы представляют собой текущие снимки и не могут быть напрямую использованы в качестве приращений на этой неделе.

Экспорт временной таблицы очищается после завершения чтения. Полная информация по этому вопросу хранится в `weekly-input.json` (авторитет `0600`), а реферат - `briefs/<ID данных>.md`; они принадлежат моей деловой информации и не будут отправлены или обнародованы, а исходный текст не будет прикреплен к карте Фейшу. После того как входной файл будет перезаписан новыми данными, старые события в очереди не будут ошибочно использовать новые данные; Я управляю полным историческим обзором в соответствии с моим собственным сроком хранения.

Когда я вхожу в систему или истечет срок действия моего разрешения, будет выдана только одна карточка с вопросом. Событие `brief.ready` не будет, и последний файл не будет использоваться в качестве результатов этой недели. После восстановления нажимаю «Продолжить» и перечитываю полностью; выберите «Сначала пропустить этот выпуск», чтобы завершить этот цикл и прочитать еще раз в следующее запланированное время; временные ошибки интерфейса, как и ожидалось, завершатся сбоем и будут обработаны существующим механизмом центра.

<a id="section-24"></a>
## Уведомление Фейшу

Правило по умолчанию регистрирует канал `feishu`. Замените `ou_REPLACE_ME` на свой open_id; добавьте `user` этого человека и существующий ключ канала в `channels.feishu`, у которого уже есть `config.json`. Повторно используйте уже работающий канал Feishu и не открывайте другой канал мониторинга. Если вы еще не подключились, нажмите [Конфигурация канала](../../../skills/agent-autoloop/SKILL.md#section-76) для завершения; при настройке новых ключей или разрешений сначала получите разрешение.

Используйте личную идентификацию для чтения деловой информации и информируйте об использовании идентификации робота. По умолчанию оно отправляется только этому человеку; сервис раздаст карту всем каналам, на которые она настроена, и нет функции индивидуального выбора получателей по правилам. Для задач, содержащих личную информацию, вам следует использовать платформу, которая позволяет вам общаться только в частном порядке и не вмешиваться в общие групповые каналы. Не отправляйте в репозиторий ключи, фактические open_ids, токены таблиц или бизнес-данные.
