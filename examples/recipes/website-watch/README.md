# Проверка веб-сайта и устранение неисправностей.

Внешняя машина проверяет веб-сайт, неисправность передается агенту по техническому обслуживанию, и процесс завершается после восстановления. Запускать фиксированный скрипт каждые 5 минут; не вызывайте модель в обычном режиме, не отправляйте повторно задачи и не отправляйте уведомления, если исключение продолжается, а также обновляйте исходную карту при восстановлении.

<a id="section-5"></a>
## Как включить

1. Скопируйте этот каталог в `~/.agent-autoloop/work/website-watch/`. Каталог доступен для чтения только мне. Компьютер, на котором выполняется сценарий проверки, должен находиться за пределами проверяемой службы, чтобы предотвратить одновременную остановку сервера и остановку проверки.
2. Поместите `SKILL.md` в `~/.codex/skills/website-watch/`; Код Клода в `~/.claude/skills/website-watch/`.
3. Объединить `sources`, `agents`, `channels` и `rules` из `rules.json`. В двух местах `worker` заменяется на компьютер-получатель заказов; `cwd` для правил проверки указывает на скопированный каталог шаблона, а `cwd` для правил устранения неполадок указывает на ваш собственный каталог кода. Часовой пояс: `Asia/Shanghai`.
4. Измените `site.json`: введите номер своего сайта, имя, работоспособный URL-адрес и текст, который должен содержать ответ. Пример доменного имени - это всего лишь заполнитель, и его нельзя использовать в качестве цели принятия. Адрес не содержит пароль учетной записи, параметры запроса или фрагменты; интерфейсы работоспособности, требующие аутентификации, должны сначала изменить сценарий проверки в соответствии с собственными проектными соглашениями.
5. Права доступа: `read`. Агент обслуживания по умолчанию считывает только локальный код; HTTP-запросы завершаются фиксированными скриптами проверки. Для проверки онлайн-логов или выполнения утвержденных действий необходимо зарегистрировать существующие инструменты в руководстве по обслуживанию основного проекта. Команды нельзя получить из событий.
6. Запустите `agent-autoloop check`, а затем подключите локальную поддельную службу HTTP в выделенном центре тестирования для проверки исключений, постоянных исключений и восстановления. Не тестируйте реальный веб-сайт, который не работает.

<a id="section-14"></a>
## Проверка калибра

Успех должен соответствовать как HTTP 200, так и содержать непустой текст, указанный `contains`. Никакого прыжка не будет; соединение, тайм-аут чтения (20 секунд) или несоответствие содержимого будут записаны как исключения, а тело ответа не будет выведено. В этом примере сообщается о первом сбое; «три последовательных» счетчика внутреннего мониторинга не используются, чтобы предотвратить сохранение шаблоном другого набора состояний. Если на веб-сайте уже реализована система устранения дребезга тревог, к ее тревогам следует обращаться напрямую как к событиям.

Невосстановленные исключения сохраняются в карточке уведомлений о проблемах центра. Скрипт проверяет только карточку, соответствующую текущему сайту; он не будет повторно отправлять карту, пока она открыта. Во время восстановления дело закрывается и генерируется событие `site.recovered`, позволяющее агенту обслуживания проверить оставшиеся вопросы. **Не нажимайте «Обработано» заранее, чтобы закрыть невосстановленные карточки исключений**: Закрытие вручную означает, что это напоминание обработано, а следующая проверка все равно не удастся и о ней будет сообщено снова. Одна и та же инспекционная группа используется только для этого одного объекта, и название остается неизменным; несколько сайтов используют независимые источники, имена правил, группы и номера сайтов; каждый набор `emits.source` должен соответствовать только `when.source` правил обработки этого сайта, чтобы избежать отправки сигналов тревоги с других сайтов в неправильный проект.

Восстановление HTTP не означает, что браузер или все бизнес-функции проходят. Когда вам необходимо самостоятельно восстановить подключение к веб-странице, вход в систему или разрешения, агент обслуживания использует `ask`, чтобы оставить список дел; этот цикл завершен, и бизнес не будет повторяться повторно.

<a id="section-22"></a>
## Уведомление Фейшу

Правило по умолчанию регистрирует канал `feishu`. Замените `ou_REPLACE_ME` на свой open_id; добавьте `user` этого человека и существующий ключ канала в `channels.feishu`, у которого уже есть `config.json`. Повторно используйте уже работающий канал Feishu и не открывайте другой канал мониторинга. Если вы еще не подключились, нажмите [Конфигурация канала](../../../skills/agent-autoloop/SKILL.md#section-76) для завершения; при настройке новых ключей или разрешений сначала получите разрешение.

Используйте личную идентификацию для чтения деловой информации и информируйте об использовании идентификации робота. По умолчанию оно отправляется только этому человеку; сервис раздаст карту всем каналам, на которые она настроена, и нет функции индивидуального выбора получателей по правилам. Для задач, содержащих личную информацию, вам следует использовать платформу, которая позволяет вам общаться только в частном порядке и не вмешиваться в общие групповые каналы. Не отправляйте в репозиторий ключи, фактические open_ids, токены таблиц или бизнес-данные.
