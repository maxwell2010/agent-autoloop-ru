<a id="section-6"></a>
# Agent Autoloop: настройка и управление

Сервис назначает работу по доверенным правилам и сохраняет состояние между циклами. Источники, исполнители и каналы сами подключаются к ядру. Общей веб-панели нет. Поддерживаются macOS и Linux. Установка описана в [INSTALL](../../INSTALL.md).

Отвечайте пользователю на русском языке. Команды, поля JSON, маршруты API, переменные среды и имена прав не переводите. В обычном тексте используйте короткие дефисы.

<a id="section-10"></a>
## Состояние и ответы

`agent-autoloop status` показывает подключения, вопросы, работу и расходы. `status --json` возвращает `/v1/state`. `why <цикл>` показывает события, версию правил и результат, а `why <цикл> --json` - исходные факты.

`answer <карточка> <номер>` выбирает ответ. В CLI нумерация начинается с 1; в HTTP и MCP поле `choice` начинается с 0. `resolve <карточка> <итог>` закрывает карточку с пояснением. `stop <цикл>` останавливает цикл; подтверждение требует завершения группы процессов.

Расходы учитываются по времени завершения за сегодня и последние семь дней в часовом поясе правил. Повторные попытки суммируются; отсутствующие сведения не считаются нулем. При продолжении сессии учитывается прирост относительно сохраненной базы. Базы хранятся в `worker/usage/`; после удаления базы или 90 дней без использования показатель может временно отсутствовать. Ручное продолжение той же сессии влияет на следующий прирост.

<a id="section-18"></a>
## Изменение правил

Редактируйте `~/.agent-autoloop/rules.json`, затем выполните `agent-autoloop check`. Правила применяются автоматически. При ошибке или недоступном файле работающий сервис сохраняет последние корректные правила и отправляет карточку.

`rules explain` показывает локальные правила и следующие запуски. `emit <тип> --dry-run` показывает назначение события без обращения к сервису и записи в журнал.

Агент, каталог, Skill и права определяются доверенным правилом. Внешний текст не может менять их. Полученный цикл сохраняет свою конфигурацию до завершения. Выбирайте `timezone` владельца, например `Asia/Barnaul`, не меняя существующую настройку произвольно. `parallel` разделяет дела по объектам и ограничивает параллельность группы; дополнительно действует емкость исполнителя. Без него все правило образует одно дело. `resume: true` сохраняет контекст между событиями; учитывайте риск сохранения недоверенных данных.

<a id="section-36"></a>
## Инструкции обработки

Размещайте инструкции в Skill либо в `prompt` доверенного правила. Готовые [сценарии](../../README.md#сценарии) содержат правила, Skill и настройку. Первая строка последнего сообщения агента - итог. Для временной ошибки с автоматическим повтором используйте `FAILED:`, при отсутствии работы - `NOTHING:`. Старые китайские маркеры сохранены; также читаются `НЕ ВЫПОЛНЕНО` и `НЕТ ЗАДАЧ`.

Дополнительные действия задаются JSON-блоком `agent-autoloop`: `ask`, `notice`, `resolve`, `later`, `events`. Имена полей не переводите. Когда нужен человек, запишите вопрос через `ask` и завершите процесс. Не ждите внутри цикла и не назначайте постоянные повторы препятствия, которое может устранить только владелец. Укажите сделанное, непроверенные пункты и оставшиеся шаги; не повторяйте завершенные операции при исправлении результата.

Закрывайте через `resolve` только карточки из `open` после проверки всех утверждений в источнике. `notice` с `fyi: true` сразу закрывается после отправки и не подходит для неустраненной проблемы. Полная структура: [протокол](../../docs/protocol.md).

<a id="section-44"></a>
## Подключение источника

Источник регистрируется в `sources`, webhook указывает `adapter`. Встроены GitHub и GitLab. Секрет подписи находится в `AGENT_AUTOLOOP_SECRET_<ИМЯ_ИСТОЧНИКА>` с заглавными буквами и заменой дефисов на `_`; пустой секрет не разрешает вход.

Опрос внешней системы можно оформить правилом со скриптом. Возвращайте стабильные ID через разрешенный правилом `emits`. Повторный ID одного источника учитывается один раз. Продвигайте курсор только после надежной передачи результата либо читайте с перекрытием и дедупликацией. Внешние данные не выбирают команды, каталоги, права или получателей. Примеры подключения: [плагины](../../docs/plugins.md).

<a id="section-52"></a>
## Подключение агента

В `agents` поле `worker` указывает исполнителя, `use` - адаптер. Поддерживаются `claude`, `codex`, `dsh`, `command`, `acp`; дополнительные параметры зависят от адаптера. `read`, `edit`, `full` у Codex соответствуют `read-only`, `workspace-write`, `danger-full-access`, у Claude Code - `plan`, `acceptEdits`, `bypassPermissions`.

`read` не изолирует все секреты системного аккаунта. `command` не ограничивает произвольную программу; передавайте аргументы массивом и не исполняйте недоверенный текст через shell. ACP полагается на соблюдение протокола агентом и ограничивает только операции, для которых тот запрашивает разрешение. Проверяйте реальные права фонового CLI, сети и браузера. Не расширяйте доступ до `full` только из-за недоступного инструмента. Для изоляции используйте отдельный аккаунт или контейнер.

Браузерное подключение берется только из доверенного правила или Skill. Передавайте ему ограниченные веб-шаги, сохраняя бизнес-логику и результат сервиса в главной задаче. После разрыва проверьте выполненные действия и продолжайте только оставшиеся; не отправляйте формы повторно. Восстановление входа или соединения владельцем запрашивается через карточку.

<a id="section-76"></a>
## Подключение канала

Канал должен присутствовать в `rules.json` и `config.json`; во втором хранится его ключ. У Feishu задайте `answerers` в правилах и ID пользователя в конфигурации. В приложении Feishu должен работать только один слушатель нажатий карточек.

Для DingTalk, WeCom, Slack, Discord используйте `webhook` с полями `use`, `platform`, `url`. Потерянное подтверждение отправки может привести к повторному сообщению. Для текстовых каналов можно включить `links: true`: любой обладатель ссылки сможет ответить на конкретную карточку в течение семи суток. Не публикуйте ссылки.

Каналы принадлежат всему сервису; правило не выбирает отдельного получателя. Частные данные не направляйте в общие каналы. Уведомления рабочего стола видны только на компьютере с графическим сеансом; иначе используйте CLI или внешний канал.

<a id="section-97"></a>
## Конвейер доставки

`delivery` использует настройки `ops/delivery.json` только из `main`, метки доставки, GitHub checks и команду ревью. Нужны авторизованный `gh` и программа ревью. Контракт настроек и меток: [протокол доставки](../../docs/protocol.md#section-397).

Код PR не выгружается в рабочее дерево (checkout). Его код, тесты, конфигурация и hooks не запускаются. Ревью получает текстовый снимок Git. По умолчанию Codex работает в read-only sandbox без пользовательской конфигурации и памяти. Другая команда ревью должна обеспечивать те же ограничения.

Перед слиянием повторно сверяются коммит, целевая ветка, метки и `main`. Непрозрачные слияния трех и более родителей и чрезмерные diff не разрешаются автоматически. Найденные проблемы требуют исправленного нового коммита. Только ревью не разрешает слияние. Подтвердите полный набор checks, отключение автоматического слияния, успешный Ship и фактическую версию health endpoint. Документы не должны скрывать неопубликованные изменения кода. Завершенная доставка не откатывается из-за последующего выпуска.

GitHub Actions фиксируются полным SHA. Защита веток и права GitHub настраиваются отдельно; плагин их не заменяет.

<a id="section-146"></a>
## MCP и отзыв ключа

`agent-autoloop mcp` работает через stdin/stdout с локальными ключами. Доступны `status`, `why`, `answer`, `resolve`, `stop`, `emit`, `tell` согласно имеющимся ключам. Это полномочия владельца; вызывающие пользователи не различаются. Не подключайте MCP к пользовательской конфигурации CLI исполнителя, иначе агент сможет отвечать на собственные карточки.

`key remove <source|worker|channel|owner> <имя>` немедленно отзывает ключ, включая длительные опросы и подписки. Уже полученная работа использует отдельный токен цикла.

<a id="section-154"></a>
## Сервер и отдельные исполнители

Оставьте hub на loopback и настройте HTTPS reverse proxy. `hub.listen` имеет вид `хост:порт` или `[IPv6]:порт`; отдельный номер порта не принимается. `hub.publicUrl` задает внешний HTTPS URL.

На сервисе создайте `key new worker <имя>`. На втором компьютере после установки выполните `join <HTTPS-адрес> --worker <имя> --key <ключ>`. В правилах укажите тот же `worker`. Исполнитель подключается сам и не требует входящего порта. Ключи не записываются в репозиторий и публичные примеры.

<a id="section-165"></a>
## Журнал и восстановление

Журнал фактов - источник истины. Проекции и индексы восстанавливаются из него; не меняйте бизнес-данные в обход журнала. `why` объясняет цикл, `/v1/stream` продолжает чтение с номера записи.

`backup [каталог]` работает и при запущенном сервисе. Копия содержит базу, главный ключ, конфигурацию, правила и `secrets.env`; храните ее как секрет. Перед `restore <каталог>` остановите сервис. Ручная копия должна сохранять вместе `hub.db` и `master.key`; без ключа прежние токены и ссылки недействительны.

<a id="section-173"></a>
## Версия, обновление и удаление

`--version` показывает tag и коммит; коммит вне выпуска отмечается как неопубликованный. Адаптация устанавливается из своего репозитория. При отсутствии release tag обновляется `main`; не выдавайте непроверенный коммит за проверенный выпуск.

`uninstall` удаляет программу и службу, сохраняя данные. `--yes` пропускает подтверждение. Перед сменой источника создайте резервную копию и удалите прежнюю установку; не заменяйте чужую конфигурацию без проверки.
